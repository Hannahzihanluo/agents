## 一、概述

### 1.1 需求背景

KA 项目流程变革要求项目组在**统一上下文**上工作：项目信息不再散落在群聊、文档、CRM 各处，智能体与人基于同一份项目上下文协作，实现「AI 输出初稿 → 人确认/修正 → 沉淀知识库」的闭环。

智能体平台现有公司知识仓库、客户知识空间与飞书群智能体能力，但缺少**项目空间**这一承上启下的载体：它向上为 AI 工作台提供项目上下文与应用入口，向下组织客户、知识、成员与任务，并为 **KA 主理智能体**提供能力挂载的边界。本需求定义智能体平台侧的项目空间能力，以及挂载其上的 KA 试点 skill 组。

## 三、需求正文

### 1. 产品定义

**项目空间**是智能体平台上围绕一个客户项目的能力载体：它关联客户与知识、维护项目统一上下文、定义成员授权、承载任务清单，并为 KA 主理智能体提供能力挂载的边界。

**项目类型**分为 KA 项目 / SKA 项目 / 个人项目：KA 与 SKA 项目面向客户经营，必须关联客户并同步商机信息；个人项目面向个人工作整理，不强制关联客户，不展示营销阶段。

**KA 主理智能体**是平台上唯一的 KA 项目主理智能体。每个项目群里的都是同一个主理智能体，不同的是它**按群挂载的项目空间**——群与项目空间绑定后，主理智能体在该群中的一切理解、产出与跟进都基于所挂载的项目空间进行，各项目数据相互隔离。

面向角色：销售/售前、需求调研/解决方案、项目经理、交付/客成、平台运营。

### 2. 处理流程

**项目建立**：
```
确认合作 → 创建项目空间（选择项目类型/关联客户/关联历史项目）
→ KA/SKA 项目自动查询客户进行中商机，商机阶段与信息同步至项目摘要
→ 在「关联群」tab 一键创建项目群并自动邀请已配置成员入群
→ KA 主理智能体自动入群并挂载该项目空间与 skill 组合
→ 输出项目初始化摘要 → 项目经理确认后启动
```

**日常运行（统一上下文维护）**：
```
群消息/文档变更/CRM 阶段变更 → 智能体持续接收并理解（按群消息监听配置执行）
→ 识别影响项目上下文的变更 → 生成更新建议
→ 项目经理确认 → 写入项目摘要（版本可追溯）
```

**方案产出（skill 调用）**：
```
用户在工作台或群内发起 → 智能体基于项目统一上下文 + 知识库执行 skill
→ 输出初稿（带引用溯源）→ 人审核/迭代 → 定稿沉淀
（项目空间 + 公司知识仓库 + 客户知识空间）
```

### 4. 原型及需求说明

#### 4.1 项目空间 — 创建与关联客户

**原型：** 整合版原型 · 资源库 → 项目空间 →「+ 创建项目空间」

**需求说明：**

- **整体功能说明：**
  平台运营或项目经理在智能体平台创建项目空间：先选择**项目类型**（KA项目/SKA项目/个人项目，默认 KA 项目），再填写项目名称、关联客户知识空间（可搜索多选）、关联历史项目（可搜索多选）。KA/SKA 项目选择客户后，系统查询该客户**进行中的商机阶段与信息**并展示，创建后自动同步至项目摘要。

- **逻辑处理说明：**
  - 项目类型决定后续规则：KA/SKA 项目**必须关联客户**（未选择时拦截提示），个人项目不强制
  - KA/SKA 项目选中客户知识空间后，实时查询 CRM 中该客户进行中的商机：商机阶段（CR1-CR7）、商机名称、预计金额、商机负责人、下次关键动作，在创建弹窗内展示查询结果
  - 创建成功后，商机阶段与信息自动写入项目摘要「商机信息」区块，项目阶段取自商机当前阶段；后续 CRM 商机变更自动触发摘要更新建议（走 4.2 确认流程）
  - 关联客户后自动带入：客户基本信息（行业、合同金额）、历史对接记录、客户知识空间内容
  - 自动从公司知识仓库检索同类项目最佳实践（即关联历史项目），关联到本项目知识视图
  - 创建时不再配置项目群；建群与监听配置在项目详情「关联群」tab 完成（见 4.7）
  - 项目初始化摘要包含：商机信息、客户背景、同类项目参考、初始待办，**项目经理确认后项目正式启动**

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 项目类型 | 单选：KA项目/SKA项目/个人项目 | 必填，默认 KA 项目；决定客户是否必选与阶段标签展示 |
| 项目名称 | 文本输入 | 如「远航物流集团 · 智能调度平台项目」 |
| 关联客户知识空间 | 可搜索多选 | KA/SKA 项目必选；绑定后自动带入客户信息并触发商机查询 |
| 关联历史项目 | 可搜索多选（选填） | 用于方案推荐与最佳实践参考 |

#### 4.2 项目空间 — 项目摘要与自动更新

**原型：** 整合版原型 · 项目空间详情 →「项目摘要」tab

**需求说明：**

- **整体功能说明：**
  项目摘要是项目统一上下文的核心：商机信息、项目目标、当前阶段、关键结论、分工、风险概况，一页看清项目全貌。KA/SKA 项目创建时基于 CRM 商机自动生成初稿，运行中自动维护更新，用户可从摘要逐层查看渐进明细文档。

- **逻辑处理说明：**
  - 摘要首屏展示「商机信息（CRM 同步）」区块：商机阶段、商机名称、金额、负责人、下次关键动作；CRM 商机变更时生成摘要更新建议
  - 智能体持续接收**绑定群全部消息**（按 4.7 监听配置执行）、项目文档变更、CRM 阶段变更，识别影响项目上下文的变更（关键决策、需求变更、阶段推进、风险变化）
  - 识别到变更后生成**更新建议**（变更内容 + 依据来源），推送给项目经理
  - **项目经理确认后才写入**摘要；每次更新保留历史版本，可回溯、可回滚
  - **摘要提取规则入口在摘要卡片上**（「提取规则」按钮打开编辑弹窗），不单设 tab：默认使用平台配置，项目级可修改（如哪些变更类型需要确认、确认人是谁）
  - 摘要中的每项结论支持**渐进明细查看**：点击可钻取到对应的纪要、报告、方案版本等原始文档

---

#### 4.3 项目空间 — 用户授权

**原型：** 整合版原型 · 项目空间详情 →「用户」tab

**需求说明：**

- **整体功能说明：**
  项目负责人定义项目成员的角色与职责，关联飞书用户。授权结果驱动三处行为：项目空间可见范围、待办按角色指派、智能体产出确认人路由。一键创建项目群时，已配置成员自动被邀请入群（见 4.7）。

- **逻辑处理说明：**
  - 角色模板按项目类型预置（销售负责人/售前架构师/项目经理/交付工程师/客户成功经理等），可增删
  - 基于用户授权校验项目空间查看权限：项目成员可读写，非成员上级只读，无关人员不可见
  - 数据按客户维度隔离，与平台既有权限体系一致
  - 待办支持按角色指派（如「售前架构师」），系统自动匹配项目成员
  - 智能体产出需要人工确认时（如方案定稿、摘要更新），按职责路由到对应确认人

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 成员 | 按飞书组织选择 | 至少指定一名项目负责人 |
| 角色 | 从角色模板选择 | 决定权限与确认路由 |
| 职责说明 | 文本输入（选填） | 如「负责 TMS 对接方案」 |

#### 4.4 任务模块 — 标准任务能力与统一任务列表

**原型：** 整合版原型 · 项目空间详情 →「任务清单」tab

**需求说明：**

- **整体功能说明：**
  平台定义**标准任务能力**（统一任务实体），所有来源的任务在同一任务列表展示与处理。任务有两类实现：
  - **关联项目的任务**：项目任务清单，承载项目执行过程中的行动项（群识别、skill 拆解、人工创建）
  - **关联智能体的任务**：由智能体创建给用户的任务（来源标记为创建智能体，不限于 KA 主理智能体）；同时支持**对接其他业务系统**（如 CRM、审批系统）产生的任务，映射为标准任务后进入同一列表

- **字段说明（标准任务实体）：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 任务名称 | 文本输入 | 必填 |
| 所属项目 | 关联项目空间 | 项目任务必填；智能体/外部系统任务可为空（个人任务） |
| 处理人 | 飞书用户，**可多选** | 至少 1 人；多人任务任一处理人完成即流转（可配置为全部完成） |
| 开始时间 | 日期时间 | 默认创建时间 |
| 截止时间 | 日期时间，精确到时分秒 | 逾期判断依据 |
| 确认人 | 飞书用户，**可无** | 有确认人时，处理人完成后需确认人确认才关闭 |
| 来源 | 系统标识 | 群聊识别 / skill 产出（xx skill）/ 智能体创建（xx 智能体）/ 外部系统（系统名）/ 人工创建 |
| 状态 | 系统流转 | 待办 / 执行中 / 待确认 / 已完成 / 逾期 / 阻塞 |

- **逻辑处理说明：**
  - **统一任务实体**：项目任务、智能体任务、外部系统任务共用同一实体与列表，按来源标识区分；列表支持按项目/来源/状态/处理人筛选
  - **飞书待办同步**（默认通道）：任务同步生成飞书待办，处理人可在飞书待办中直接查看、完成、转交，结果双向同步回平台任务列表
  - **外部系统对接**：通过开放接口将其他业务系统任务接入为标准任务（字段映射 + 状态回写），与内部任务同一列表显示；接入配置见第四章
  - **确认人流转**：无确认人——待办 → 执行中 → 已完成；有确认人——待办 → 执行中 → 待确认 →（确认）已完成 /（驳回）执行中；逾期未完成标记「逾期」，任一阶段可标记阻塞（需填原因）
  - **项目任务创建来源**：① 群智能体从群聊识别任务分派；② skill 产出附带的结构化待办（经任务拆解 skill 人工确认）；③ 人工创建。**来源统一展示为「xx skill / xx 群」格式**
  - **智能体任务**：智能体产出需要用户跟进的事项时（如「请补充客户数据字典」），可直接为用户创建任务，来源标记该智能体，进入用户任务列表并同步飞书待办
  - **提醒与升级**：智能体可主动查询任务执行状态（临近截止未处理、已逾期），据此执行跟进提醒（含群内 @ 处理人，见 4.7）与状态回写；提醒与升级沿用群智能体既有机制（早报提醒、到期前提醒、逾期分级升级）
  - 详细规则见《[prd]项目空间与飞书群智能体-26年06月28日 v01》，本需求不重复定义

#### 4.5 项目空间 — 文件与飞书云文件夹同步

**原型：** 整合版原型 · 项目空间详情 →「文件」tab

**需求说明：**

- **整体功能说明：**
  项目空间创建时，自动在飞书云空间**同步创建同名项目文件夹**（含阶段子文件夹：需求调研/方案/POC/交付），项目空间「文件」tab 与该飞书文件夹双向同步——项目文档在平台与飞书两侧保持一致，成员在任一侧都能访问最新版本。

- **逻辑处理说明：**
  - **同步创建**：项目空间创建成功后，自动创建飞书云文件夹「{项目名称}」，并按项目阶段预置子文件夹；文件夹按项目成员授权自动共享（与「用户」tab 成员一致，成员变更同步调整权限）
  - **双向同步**：平台侧上传的文档、skill 产出定稿自动同步至飞书文件夹对应阶段目录；飞书文件夹中新增/更新的文档同步回项目空间文件视图
  - 文件按阶段分组展示，保留版本历史；skill 产出初稿仅在定稿后同步飞书文件夹（过程稿留在平台侧）
  - 项目归档后飞书文件夹转为只读保留；删除项目空间不删除飞书文件夹（防误删，仅解除同步关系）
  - 同步异常（权限不足/网络失败）记录并告警，支持手动重试

#### 4.6 KA 主理智能体 — 项目空间挂载与配置

**原型：** 整合版原型 · 资源库 → 项目空间列表（关联智能体入口）、项目空间详情 →「项目技能」tab

**需求说明：**

- **整体功能说明：**
  平台存在唯一的 KA 主理智能体，服务所有 KA 项目群。项目绑定群后，主理智能体自动将该项目空间挂载到对应群。项目列表卡片展示**关联智能体个数**，点击可查看智能体名称列表并设置**项目默认智能体**；项目负责人在项目空间设置中调整本项目挂载的 skill 组合与行为参数。

- **逻辑处理说明：**
  - **一智能体多项目**：主理智能体同时存在于多个项目群，通过群定位挂载的项目空间——在某群中接收消息、回答问题、产出内容时，仅使用该群所挂载项目空间的上下文与知识，各项目数据相互隔离
  - **关联智能体配置**：项目可关联多个智能体；项目列表卡片显示关联个数，点击弹出名称列表，单选设置默认智能体（群会话与任务默认由其处理）；列表页支持**按关联智能体筛选**项目
  - 挂载的默认 skill 组合：试点 skill 组（4.8-4.12）+ 平台标准 skill（文档处理、数据分析等），项目级可增删
  - 可修改的项目级配置：项目摘要更新 skill（确认范围/确认人）、群智能体行为参数（沿用既有配置体系）、skill 挂载组合
  - 不同项目模板对应不同预设：KA 攻坚（高频提醒）、签约交付（标准提醒）、客户运营（低频提醒）
  - 修改即时生效，所有智能体操作可回溯、可撤销

#### 4.7 群协同 — 关联群管理与全量消息接收

**原型：** 整合版原型 · 项目空间详情 →「关联群」tab

**需求说明：**

- **整体功能说明：**
  项目组成员日常仍在飞书群中协同工作。项目详情「关联群」tab 承载群的创建、绑定与监听配置：**一键创建并关联**项目群（自动邀请已配置成员入群），或搜索绑定已有群聊；KA 主理智能体作为群成员**接收全部群消息**（无需被 @ 也在持续理解项目进展），基于该群挂载的项目空间理解上下文，并**自主判断何时响应、何时保持沉默**。

- **关联群管理逻辑：**
  - **一键创建并关联**：按项目名称生成群名（如「云途供应链-项目组」），自动将「用户」tab 已配置成员邀请入群，创建完成即绑定本项目；每个项目仅可创建一个主群，已关联时拦截提示
  - **绑定/解绑**：可搜索绑定已有群聊（如客户关系群、POC 临时群）；解绑后智能体退出该群并停止监听
  - 绑定后 KA 主理智能体自动入群，开始接收群消息；该群中智能体的上下文即为本项目空间

- **群消息监听配置（按项目配置，默认全开启）：**

| 配置项 | 说明 |
|---|---|
| 群消息监听总开关 | 关闭后智能体不再处理该群消息（仍在群内） |
| 每日定时总结 | 每日定时（默认 09:00）自动查询前一日群消息并生成总结 |
| 自动更新项目摘要 | 基于总结内容识别上下文变更，生成更新建议（项目经理确认后写入，见 4.2） |
| 自动拆解任务 | 从群消息拆解行动项，推送对应角色确认后进入任务清单（同步飞书待办，见 4.4/4.11） |

- **智能体响应策略：**

| 智能体行为 | 触发场景 | 响应方式 |
|---|---|---|
| 主动响应 | 识别到任务分派/承诺确认、关键决策或风险、能直接回答的项目问题、讨论结论需要落锤 | 群内推送卡片或回复；把握不足时先推候选卡片等人确认 |
| 静默处理 | 项目相关的背景讨论但无需即时动作 | 仅作为上下文沉淀，不打扰群聊 |
| 完全忽略 | 闲聊等与项目无关内容 | 不处理 |
| 定时行为 | 每日早报、逾期提醒、群置顶摘要更新 | 按配置时间执行（免打扰时段除外） |

  - 群内 @智能体 的问答自动定位到本项目上下文回答，引用来源（消息时间+发言人）便于回溯
  - 消息合并、意图分类、把握度判断、免打扰等底层机制沿用《[prd]项目空间与飞书群智能体-26年06月28日 v01》已定义规则

- **主动 @ 飞书用户：**
  机器人可在群内**主动 @ 项目成员**，推动事项闭环，而非仅被动响应。

| @ 场景 | 触发条件 | @ 对象 |
|---|---|---|
| 任务下发/转交 | 任务拆解确认下发、任务转交 | 处理人（多人全部 @） |
| 确认请求 | 摘要更新建议、方案定稿、任务拆解待确认 | 确认人（按职责路由） |
| 临期/逾期提醒 | 任务临近截止未处理、已逾期 | 处理人；逾期升级时加 @ 项目经理 |
| 风险预警 | 识别到高级别风险 | 项目经理 |

  - @ 消息附操作卡片（确认/驳回/完成/查看详情），处理结果直接回写对应模块，无需跳转
  - 克制原则：同一事项合并为一条提醒，不重复 @；免打扰时段不 @（高级别风险除外）；@ 对象严格按项目成员与职责路由，不 @ 无关成员
  - 主动 @ 能力对平台上其他智能体开放（不限于 KA 主理智能体），智能体创建任务、发起确认时可调用

#### 4.8 调研方案生成 skill

**需求说明：**

- **整体功能说明：**
  用户将客户访谈纪要（飞书文档/录音转写）导入，智能体提取结构化需求，关联历史同类项目，生成需求调研报告初稿。

- **逻辑处理说明：**
  - 从纪要中逐条提取需求：业务诉求/量化目标/性能约束/集成约束/预算约束等，**每条附原文引用位置**
  - 自动关联公司知识仓库中的同类项目（如「顺捷物流智能调度」），标注匹配度
  - 人审核逐条处理：**接受 / 修改 / 驳回**；驳回项回流重新提取
  - 审核完成后生成需求调研报告初稿，人确认定稿
  - 修正内容结构化记录（改了哪条、改成什么），用于每周提示词迭代
  - 定稿自动沉淀：项目空间 + 客户知识空间

#### 4.9 需求解决方案 skill

**需求说明：**

- **整体功能说明：**
  基于已确认的需求与公司方案库，智能体推荐方案框架与类似案例，生成一页纸方案初稿，支持人工迭代直至定稿。

- **逻辑处理说明：**
  - 方案框架按已确认需求逐条映射推荐，类似案例给出匹配度与知识库引用溯源
  - 一页纸方案支持版本迭代（目标 ≤3 轮）：每轮合并人工修正意见生成新版本，并输出**本轮修正点摘要与修正率**
  - 定稿必须人工确认；定稿后沉淀：项目空间 + 公司知识仓库（走入库流程，审核后发布）+ 客户知识空间
  - 方案定稿后可触发任务拆解 skill，生成交付行动项

**需求说明：**

- **整体功能说明：**

- **逻辑处理说明：**
  - 报告围绕方案中承诺的量化目标逐项验证（如响应时长、成本降低比例、峰值稳定性）
  - 初稿由交付/客成确认后输出正式版
  - 报告沉淀至项目空间，并可选同步客户知识空间

#### 4.11 任务拆解 skill

**需求说明：**

- **整体功能说明：**
  智能体从方案、报告、群讨论中拆解行动项，**生成飞书待办**，人工确认后下发到责任人。

- **逻辑处理说明：**
  - 拆解结果包含：事项、建议负责人（按角色匹配）、建议截止时间（精确到时分秒）、优先级
  - **必须经人工确认**后才正式下发；确认时可修改负责人与时间
  - 下发后进入项目任务清单，纳入统一提醒与升级机制
  - 待办支持转交，转交记录保留

## 四、关联系统处理

> 本章为技术附录，描述与现有系统的集成，供开发评审使用。

### 4.1 与现有平台能力的关系

| 现有能力 | 集成方式 |
|---|---|
| 客户知识空间 | 项目空间绑定客户后读取；重大决策/里程碑选择性回写，日常待办不同步 |
| CRM 商机 | 创建 KA/SKA 项目时查询客户进行中商机（阶段/金额/负责人/下次动作）写入项目摘要；商机变更触发摘要更新建议 |
| 公司知识仓库 | skill 检索走既有检索装配链路（权限过滤→召回→重排→引用溯源）；方案定稿走入库流水线 |
| 飞书群智能体 | 消息接入、意图分类、定时任务、配置体系整体复用，本需求扩展项目级监听配置、一键建群、主动 @ 成员与摘要更新 skill |
| 飞书云空间 | 项目空间创建时同步创建项目文件夹并预置阶段子目录；文档双向同步；文件夹权限跟随项目成员授权（见 4.5） |
| 智能体执行环境 | KA 主理智能体复用既有执行与通知通道，不另建 |
| 飞书待办 | 标准任务实体默认双向同步飞书待办；智能体通过飞书 CLI 查询待办状态并执行跟进处理（见 4.4） |
| 外部业务系统 | 通过标准任务开放接口接入外部任务（字段映射 + 状态回写），与内部任务同一列表展示处理 |

### 4.2 数据隔离与权限

- 项目空间数据按客户维度隔离；用户授权校验与平台既有权限体系一致
- 智能体仅读取绑定群的对话，不保存原始群消息，仅保存结构化提取结果
- 个人项目不关联客户时，数据按创建人维度隔离，不进入客户经营统计

### 4.3 与 AI 工作台的衔接

- 项目空间、项目摘要、任务清单、skill 产出通过平台能力开放给 AI 工作台呈现（见《[prd]AI工作台-项目空间与客户经营看板-26年07月28日 v01》）
- 工作台侧项目空间列表支持搜索与分页加载，展示项目类型；创建入口复用平台侧创建弹窗
- 工作台侧的 gitlab 云端提交同步作用于项目文档产出，不影响平台侧数据权威源

### 4.4 标准任务开放接口与飞书待办集成

- 标准任务实体（见正文 4.4）对内外统一：智能体可通过接口为用户创建任务；外部业务系统任务经字段映射接入，状态变化双向回写
- 任务与飞书待办建立映射：创建/完成/转交/逾期/待确认状态双向同步
- 智能体通过飞书 CLI 提供的待办查询与处理能力执行：按项目/负责人查询待办执行状态、识别临近截止与逾期未处理项、回写跟进结果
- 查询与处理范围限于项目空间授权成员名下的相关待办，遵循飞书侧权限约束

## 附录 A：项目摘要自动更新提示词（平台默认模板）

> 对应 4.2「项目摘要与自动更新」。平台默认配置如下，项目级可在「项目摘要 → 提取规则」中修改确认范围与确认人。

````
# 角色

你是 KA 主理智能体的「项目摘要维护模块」。你的唯一职责是：基于项目群消息、项目文档变更与 CRM 商机变更，识别影响项目统一上下文的变更，输出《项目摘要更新建议》。

你不直接写入摘要。所有更新必须经项目经理确认后生效。

# 输入

每次运行时，你将获得以下材料：
1.【当前项目摘要】最近一次确认版本的完整内容
2.【群消息】绑定项目群自上次运行以来的消息（含发言人、时间；每日定时任务为前一自然日全量）
3.【文档变更】项目空间内新增/更新的文档清单及变更摘要
4.【CRM 变更】关联客户进行中商机的字段变更（阶段、金额、负责人、下次关键动作等）

# 摘要结构（更新建议必须定位到以下区块）

- 商机信息：商机阶段（CR1-CR7）、商机名称、金额、负责人、下次关键动作
- 项目目标：项目要达成什么、量化目标
- 当前阶段：阶段进展、已完成里程碑、下一步动作
- 关键结论：客户或我方已确认的方向性结论（范围、排期、预算、目标）
- 分工：项目成员角色与职责调整
- 风险概况：风险项、等级（高/中/低）、应对措施

# 提取范围（只有以下变更才生成建议）

1. 关键决策：客户或我方明确确认的结论，或推翻了摘要中既有结论的讨论结果
2. 阶段推进：营销阶段迁移、里程碑完成或延期
3. 需求变更：范围增减、目标调整、预算或排期变化
4. 风险变化：新风险出现、既有风险等级变化、风险关闭
5. 任务与分工：影响项目结构的责任人调整、关键任务完成/逾期
6. 商机变更：CRM 侧商机字段变化（以 CRM 为权威源，直接生成建议）

以下内容一律忽略：日常寒暄、过程性讨论未定稿的内容、与项目无关的信息、仅措辞润色的文档变更。

# 输出格式

按以下结构输出《项目摘要更新建议》，无变更时输出「本次无更新建议」：

## 建议 1
- 定位区块：（商机信息 / 项目目标 / 当前阶段 / 关键结论 / 分工 / 风险概况）
- 变更类型：（关键决策 / 阶段推进 / 需求变更 / 风险变化 / 任务与分工 / 商机变更）
- 建议内容：（拟写入摘要的完整文本，直接可用）
- 依据来源：（消息时间 + 发言人原话摘要 / 文档名 + 变更位置 / CRM 字段变更前后值）
- 把握度：（高 / 中 / 低）
- 建议确认人：（按项目成员职责路由；默认项目经理）

# 规则

1. 每条建议必须附依据来源，无依据不输出；群消息依据保留原话关键措辞，便于回溯
2. 建议内容必须是可直接写入的成稿文本，不写「可能」「大概」等不确定措辞；不确定的放入依据来源说明，并将把握度标为「低」
3. 与摘要既有内容冲突时，在建议中显式标注「将替换：×××」
4. 把握度为「低」的建议，在推送时标注需人工重点核实
5. CRM 商机变更以 CRM 为权威源，即使群内无讨论也生成建议
6. 同一区块的多个变更合并为一条建议
7. 忽略免打扰时段；每日定时任务默认 09:00 执行，处理前一自然日 00:00-24:00 的材料
````
