## 一、概述

### 1.1 需求背景

智能体平台承接了来自多个业务系统的任务（case 单系统的售后工单、客成系统的服务动作、CRM 的商机跟进、天润客服的来电工单），也承接了智能体在对话与项目空间中自动派生的任务。这些任务此前分散在各自的来源系统里，处理人需要在多个系统间切换才能看到自己要做什么，任务的处理结果也无法统一回流。

同时，任务能否被正确分发，取决于平台侧的两类配置：**任务类型**决定了一个任务归属哪个业务域、创建时需要带哪些参数；**业务对接**决定了外部系统有没有资格往平台推任务、能推哪些类型的任务。这两类配置目前缺少统一的管理入口。

需要明确的边界是：**派单不由平台承担**。任务的处理人由创建任务的一方在创建时指定——外部业务系统推任务时带上处理人，平台内派生的任务由派生方指定。平台不按任务类型配置默认处理主体，也不做角色/组织范围的认领分派。原因是派单规则内嵌在各业务的流程里（谁值班、谁负责这个客户、这单该走哪个组），这些信息在业务系统侧最完整，平台再维护一套只会与业务侧不一致。

本需求解决两件事：

1. 让处理人在智能体平台有一个统一的任务执行入口，看到并处理归属自己的全部任务，无论任务从哪来。
2. 让被授权的用户能配置任务类型与业务系统对接关系，控制任务的来源与参数要求。

这两类配置的管控方式统一为**基于用户权限控制可见页面与可操作功能**，不设审核流程：能配置的人保存即生效，不能配置的人看不到入口。审核环节在实际运转中只带来等待，并不解决"谁该改什么"的问题——真正需要约束的是配置权限的授予范围，这由用户管理中的功能权限与数据管理权限承担。取消审核不取消追溯，关键配置的变更均留痕可查。

另需明确的是：**处理任务不需要选择执行方**。处理人在任务详情里填写处理说明即可办结，平台不在处理动作里区分"人工处理"与"指派智能体处理"。原因是执行方的选择与任务能否办结无关——处理人调用智能体协助是发生在对话里的行为，把它做成办结前的一次分叉，只会让最高频的"看一眼、写结论、结单"动作多两步。

## 三、需求正文

### 1. 产品定义

**任务执行**是智能体平台面向**任务处理人**的工作台入口。处理人在这里看到所有归属自己的任务（自己是处理人，或自己创建、指派给他人的任务），填写处理说明办结，或转交给他人。

**任务配置**是智能体平台面向**被授权用户**的配置入口。在这里定义平台能处理哪些类型的任务、创建时需要带哪些参数、哪些外部系统可以往平台推送任务。配置不走审核，保存即生效；谁能配置、能配置到什么范围，由用户管理中的权限决定。

**用户管理**是权限的配置入口，通过功能权限（可见页面与可操作功能）和数据管理权限（可管理的对象范围）两组授权，决定每个用户在平台上能做什么。

三者的关系是：用户管理决定谁有资格配置，任务配置定义规则，任务执行按规则运转。

### 2. 处理流程

**任务进入与处理**

```
任务产生
 ├─ 外部业务系统推送（case 单系统 / 客成系统 / CRM / 天润客服）
 │    → 平台校验该系统是否启用中、该任务类型是否在其获权范围内、是否带齐必须参数与处理人
 │    → 通过：按业务系统指定的处理人建单 → 进入该处理人的「我的任务」
 │    → 不通过：拒绝接收，记录原因
 └─ 平台内部派生（智能体对话中识别、项目空间行动项、智能体定时任务）
      → 由派生方指定处理人（对话中识别默认归发起人、项目空间行动项由拆解时指派、
        定时任务取任务配置中设定的处理人）→ 进入该处理人的「我的任务」

处理人打开「我的任务」
 → 筛选/定位任务（已完成与全部状态默认只看近 3 个月）→ 查看任务详情
 → 选择动作
     ├─ 处理：填写处理说明 → 办结（不选执行方）
     ├─ 编辑：修改任务标题、任务描述、处理人等信息
     └─ 转交他人：选择接收人 → 任务转出
 → 办结后任务进入「已完成」，如需继续跟进可重新打开
```

**任务类型配置流转**

```
用户进入 平台配置 → 任务配置（有「任务配置」功能权限才可见此入口）
 → 新建/编辑任务类型：填写业务域、类型名称、必须参数（逐项填参数名称+参数描述，可增删多项）
     （可编辑范围受「任务类型管理权限」约束，只能改自己被授权的类型）
 → 保存即生效 → 启用中（可被业务系统勾选推送）
 → 需要下线时停用 → 已停用（不再接收新任务，已有任务不受影响）
```

**业务对接配置流转**

```
用户进入 平台配置 → 任务配置 → 业务对接配置（有「任务配置」功能权限才可操作）
 → 新增业务系统：填写系统信息与对接参数 → 勾选该系统可推送的任务类型（仅限启用中的类型）
 → 保存即生效 → 启用中（正式接收该系统推送的任务）
 → 需要暂停接入时停用 → 已停用（拒收新任务，已有任务不受影响），恢复接入时再启用
 → 后续修改参数或获权范围：保存即替换生效，不设审核等待期
```

### 3. 产品信息结构图

```
智能体平台
├─ 任务执行
│   ├─ 我的任务
│   │   ├─ 筛选区（归属视角：我处理 / 我转交跟进 · 任务状态 · 任务类型 · 时间范围 · 关键词）
│   │   ├─ 统计概览（待办 / 处理中 / 已完成 / 已取消）
│   │   └─ 任务列表（按处理人视角拉平）
│   │       ├─ 归属我的主任务 → 一条
│   │       ├─ 归属我的子任务（任意层级）→ 各占一条，标注「↑ 上级任务」
│   │       ├─ 飞书待办同步状态（已同步 / 未开启同步 / 同步失败 + 重试）
│   │       └─ 行内操作（处理 / 转交 / 编辑 / 删除 / 详情 · 催办 / 收回 · 重新打开）
│   └─ 智能体任务执行
│       ├─ 定时任务列表
│       ├─ 任务配置（执行节奏 / 执行内容 / 通知方式）
│       └─ 执行记录
├─ 平台配置
│   └─ 任务配置
│       ├─ 任务类型配置
│       │   └─ 业务域 → 任务类型 → 必须参数（参数名称+参数描述，多项）/ 启用状态
│       └─ 业务对接配置
│           └─ 业务系统
│               ├─ 启用状态（启用中 / 已停用）
│               ├─ 对接参数（身份凭证/回调地址/事件订阅/数据同步/字段映射）
│               ├─ 可调用创建的任务类型（获权范围）
│               └─ 是否同步飞书待办（按业务系统控制）
└─ 用户管理
    ├─ 用户列表（角色筛选 / 姓名搜索 · 新增用户）
    └─ 新增 / 编辑用户
        ├─ 角色 · 姓名 · 登录账号 · 邮箱
        ├─ 功能权限选择（树形，控制可见页面与可操作功能）
        │   └─ … / 任务执行 → 指定用户 / 平台配置 → 任务配置
        └─ 数据管理权限（智能体 / 知识库 / 项目空间 / 技能库 / 任务类型）

平台向业务系统开放的三类能力：
- 任务分类定义 → 业务系统读取自己可创建的类型及其必须参数（仅返回获权范围内的类型）
- 主/关联任务创建 → 业务系统创建主任务或在主任务下创建子任务
- 任务查询 → 业务系统查询自己创建的任务的状态与处理结果
（具体任务流程由业务侧自行实现，平台不介入）

关系说明：
- 任务的拆解层级不设上限：对某个子任务而言，它自己就是一个待处理主任务，只是多一个关联的上级任务
- 任务的处理人由创建方在创建时指定，处理人决定任务出现在谁的「我的任务」里；平台不按任务类型派单
- 任务类型只定义业务域归属与创建时的必须参数，不配置处理主体、不配置订阅智能体
- 处理任务只需填写处理说明即可办结，不选择执行方；处理人需要智能体协助时在对话中调用
- 业务系统的获权任务类型，决定该系统能创建哪些任务；未获权类型对该系统不可见
- 任务类型保存即生效，不设审核环节；能不能配置由用户权限决定，而不是由审核决定
- 用户的功能权限决定他能看到哪些页面、能操作哪些功能；数据管理权限决定他能管的对象范围
- 飞书待办是否生成，按任务来源的业务系统的开关判定；平台内派生的任务默认生成
- 任务能不能删，看当前用户是不是创建人、管理员、或该任务类型的管理者；处理人不具备删除权
```

#### 4.1 任务执行·我的任务

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  处理人的任务主列表。进入后默认展示所有归属自己的任务，包含自己作为处理人的任务，以及自己创建后指派给他人的任务（用于跟进对方进度）。列表上方是筛选区与统计概览，下方是任务列表。处理人在这里完成日常的任务查看与推进，不需要回到任务的来源系统。

- **逻辑处理说明：**

  **归属范围**

  - 一个任务出现在「我的任务」的条件是：当前用户是该任务的处理人，或当前用户是该任务的创建人。
  - 创建人视角的任务用于跟进，创建人可以催办、可以收回，但不能代替处理人办结。

  **筛选与统计**

  - 提供五个筛选条件：**归属视角**（我处理的 / 我转交·跟进中）、任务状态（未办结 / 已完成）、**任务类型**、**时间范围**、关键词。关键词匹配任务标题与关联业务系统编号。
  - 任务类型筛选按一级业务域分组，可以选整个业务域（该域下全部二级类型），也可以选到具体的二级类型。选项只列当前列表中实际出现过的类型，不展示无任务的类型，避免选了得到空结果。
  - 各筛选条件同时生效，取交集。
  - 统计概览展示待办、处理中、已完成、已取消四个数量。数量与当前筛选结果联动：切换筛选条件后，统计数量随之刷新。
  - 点击统计标签，等同于把任务状态筛选切换到对应状态。

  **时间范围**

  - 时间范围提供「近 3 个月 / 全部时间」两个取值，**默认近 3 个月**。是否生效取决于当前的任务状态筛选：

  | 任务状态筛选 | 时间范围 | 说明 |
  |--------------|----------|------|
  | 已完成 / 全部状态 | 生效，默认近 3 个月，可切「全部时间」 | 已完成的任务只有回溯价值，越久越少被查，默认收窗让列表回到当期在办的量级 |
  | 未办结（待办+处理中） | 不生效，恒展示全部时间 | 未办结的任务无论多久之前创建都仍需处理，按时间隐藏会导致漏办 |

  - 时间范围不生效时，选择器置灰不可操作，并提示「进行中的任务不限时间，全部展示」，避免用户以为筛选失灵。
  - 落窗取的时间按条目状态区分：**已完成条目取完成时间，未完成条目取创建时间**。原因是判断一条已办结的任务"是不是近期的事"，看的是它什么时候结束，而不是什么时候创建。
  - 缺少对应时间的条目（历史数据未回填）不被隐藏，一律视为在窗内，避免筛选造成数据丢失。
  - 统计概览的数量与时间范围联动：受时间范围约束的状态（已完成、全部）按窗内计数，不受约束的状态（待办、处理中）按全部计数。

  **列表展示：处理人视角条目制**

  - 列表**不呈父子结构**，而是按处理人视角拉平：归属自己的主任务占一条；归属自己的子任务，无论它在第几层，也各自独立占一条，与主任务同级展示，不作为主任务行的缩进附属项。
  - 依据是任务层级的核心口径：**对某个子任务而言，它自己就是一个待处理主任务，只是多了一个关联的上级任务。** 对处理人来说，要做的是"这一件事"，它挂在第几层不影响他的动作。
  - 子任务行以「↑ 上级任务：XXX」标注归属关系；不归属自己的层级不出现在列表中。
  - 每行展示任务编号、名称、优先级、任务描述、流程节点与 SLA、分类、类型、来源、截止时间、创建时间、状态、**飞书待办同步状态**、处理人、创建人、备注。有下级时展示子任务进度（已完成数 / 总数）。
  - 列表按优先级排序（高 → 中 → 低），同优先级内按截止时间升序，最早到期的排前面。已完成的任务排在未完成任务之后。

  **飞书待办同步状态**

  - 列表为每条任务展示一个同步状态，让处理人知道这条任务会不会出现在飞书待办里。取值三种：

  | 状态 | 判定条件 | 处理人可见的含义 |
  |------|----------|------------------|
  | 已同步 | 待办已创建成功 | 已在飞书待办中生成条目，状态与平台双向同步 |
  | 未开启同步 | 任务来源系统的「同步飞书待办」开关为关 | 该任务只在平台内流转，不会进飞书，需在平台查看 |
  | 同步失败 | 调用飞书开放平台失败（超频、凭证失效、处理人未绑定飞书等） | 待办未生成，只在平台内可见；可点「重试」重新同步 |

  - 判定顺序是先看开关、再看结果：**来源系统开关为关时直接判为「未开启同步」，不再尝试创建待办**；开关为开才发起创建，创建结果决定「已同步」或「同步失败」。
  - 来源系统的判定口径：任务来自外部业务系统时，取该系统在业务对接配置中的开关（见 4.4）；平台内派生的任务（群聊识别、skill 产出、智能体创建、页面手动创建）不隶属任何外部系统，**默认同步**，不受开关影响。
  - **主任务与子任务的待办各自独立**：待办是发给处理人的，主任务与子任务的处理人可能不是同一个人，因此同步状态按条目各自判定与展示，子任务不继承主任务的同步结果。
  - 「重试」只出现在同步失败的行上，且只针对该条目自己的待办。重试成功后状态转为「已同步」，并在任务时间线记录重试人与时间；重试失败保持「同步失败」，可再次重试。
  - 转交任务时，原处理人的待办撤回、新处理人重新生成待办，同步状态重新判定。

  **任务删除**

  - 删除入口在两处：我的任务列表的行内操作、任务详情弹窗的标题区。两处走同一套权限判定与同一个二次确认。
  - **可删除的三类人**，满足任一即可：

  | 授权来源 | 判定条件 | 说明 |
  |----------|----------|------|
  | 任务创建人 | 当前用户是该任务的创建人 | 自己建错、建重复的任务，自己可以删 |
  | 管理员 | 当前用户角色为管理员 | 平台的超级管理口径，不受任务类型授权范围限制 |
  | 任务类型管理者 | 当前用户的任务类型管理权限范围覆盖该任务的类型 | 授权范围按业务域或按具体类型编码，取值见 4.5 |

  - **处理人不具备删除权**。处理人对任务的动作是办结或转交，不是删除——任务是别人派给他的，是否还需要做这件事由创建方或管理方判断。
  - 判定不通过时不展示删除入口。展示时，按钮上标明本次删除权的来源依据（如「管理员」「服务一条链任务类型管理权限」），二次确认弹窗中同样给出，避免用户不清楚自己凭什么能删。
  - **删除只针对主任务**。子任务的增减属于任务拆解的调整，走拆解入口处理，列表的子任务行不提供删除。
  - 二次确认弹窗需说明本次删除的连带影响，逐条列出：级联删除的下级子任务数量、已生成的飞书待办将撤回、外部来源任务将回告来源系统、删除后不可在页面上恢复。
  - **删除的执行口径**：
    - 逻辑删除，**级联删除全部下级子任务**（不限层级），不允许出现失去上级的孤立子任务。
    - 撤回该任务及其所有下级已生成的飞书待办。
    - 任务由外部业务系统推送时，回告来源系统"任务已删除"，让来源系统同步关闭自己的单据状态，避免两侧不一致。
    - 从所有列表与统计中移除，**不计入任何统计口径**。
    - 页面不提供恢复入口；执行记录按 Trace ID 留存，删除动作本身留痕（删除人、时间、删除依据、连带删除的子任务清单）。
  - **删除不等于已取消**，两者不合并统计：已取消是"这件事不做了"的业务结论，任务仍在列表与统计中可查；删除是"这条记录不该存在"，从统计中移除。任务确实不需要做但需要留档时，应使用取消而非删除。

  **行内操作**

  - 每行提供的操作随当前用户身份与任务状态变化：
    - 未办结、且当前用户是处理人：显示「处理」「转交」「编辑」「详情」
    - 未办结、已转交他人并保持跟进：显示「催办」「收回」「详情」
    - 已办结：显示「重新打开」「详情」
    - 未办结、当前用户既非处理人也非创建人：仅显示「详情」，并提示该任务的处理人是谁
    - 满足删除权限时，在上述操作之后追加「删除」（判定规则见下文「任务删除」）；删除权限与任务状态无关，已办结的任务同样可删
  - 子任务行的操作还受层级口径约束：**该节点归自己、且它的上级也归自己**时才提供处理类操作，否则仅可查看。详见《AI 工作台 - 智能体伙伴与任务中心》4.4。
  - 点击「处理」进入统一的处理弹窗，**只需填写处理说明即可办结，不选择执行方**。具体规则见《AI 工作台 - 智能体伙伴与任务中心》中任务处理章节，两端使用同一套处理逻辑与同一份任务数据。
  - 点击任意一行的空白区域，打开任务详情。

  **编辑任务**

  - 编辑入口在未办结任务的行内操作中，当前用户是处理人或创建人时可用。
  - 可编辑字段：任务标题、**任务描述**、优先级、截止时间、处理人、备注。任务描述是本轮新增的可编辑项——任务从来源系统进来时描述往往只有一句原始摘要，处理人补充上下文后，接手的人不必再回来源系统翻。
  - 不可编辑字段：任务编号、任务类型、关联业务系统编号、任务状态、创建人、完成时间。这些字段或由系统生成、或由创建方定义，改了会与来源系统不一致。
  - 处理人在编辑中被改写时，等同于转交：原处理人的飞书待办撤回，新处理人重新生成，同步状态重新判定。
  - 编辑保存后在任务时间线记录修改人、时间与变更字段。

  **扩展字段**

  - 任务详情在基础信息之后展示「扩展字段」区，用于呈现来源系统透传的冗余字段（如客户等级、区域、渠道编码、来源系统自定义标识等）。
  - 扩展字段**默认为空**。平台不预先定义字段清单，也不校验字段含义，只按来源系统推送的键值原样展示——各业务系统要带的冗余信息差异很大，平台逐个定义会永远追不上业务的变化。
  - 有值才展示：无扩展字段时整个区块不出现，不显示空占位。
  - 扩展字段只读，不参与筛选、排序与统计，也不可在平台侧编辑。它的作用是让处理人不切系统就能看到判断所需的上下文。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 任务编号 | 系统生成，不可编辑 | 平台内的任务唯一标识。子任务编号为「主任务编号-层级路径」，路径逐级追加（如 `T-1024-2-1`），层级不设上限 |
| 上级任务 | 系统关联 | 子任务行展示「↑ 上级任务：XXX」；主任务无上级时不展示该行 |
| 关联业务系统编号 | 由来源系统推送时带入，平台内派生的任务为空 | 展示为「来源系统 · 单据号」，例如「case 单系统 · #8842」，便于处理人回到来源系统核对 |
| 任务标题 | 由来源系统或创建人填写，可在编辑中修改 | 列表主要识别信息 |
| 任务描述 | 由来源系统或创建人填写，**可在编辑中修改** | 任务的背景与要求。允许处理人补充上下文，修改留痕于时间线 |
| 扩展字段 | 由来源系统推送时透传，平台不定义清单、不校验、不可编辑 | 冗余字段的键值展示，默认为空，有值才在任务详情中展示；不参与筛选与统计 |
| 任务类型 | 由来源系统或创建人指定，不可在列表内修改 | 展示为「业务域 › 来源单据 › 细分场景」三段。前两段来自任务类型配置，第三段是创建任务时指定的细分场景，不需要预先配置 |
| 优先级 | 高 / 中 / 低 | 由来源系统或创建人指定，影响列表排序 |
| 任务状态 | 待办 / 处理中 / 已完成 / 已完成（随上级关闭） / 已取消 | 由系统按处理动作自动流转，不可手工选择。上级提前办结时，其下各级未完成任务自动转为「已完成（随上级关闭）」 |
| 飞书待办同步状态 | 系统自动判定，不可手工设置 | 已同步 / 未开启同步 / 同步失败。外部系统来源取该系统的同步开关，平台内派生默认同步；主任务与子任务各自判定 |
| 处理人 | 由创建任务的一方在创建时指定（外部系统推送时带入、平台内派生时由派生方指定），可通过转交变更 | 决定任务出现在谁的列表里。平台不按任务类型派单 |
| 创建人 | 系统记录，不可编辑 | 平台内派生的任务记录派生来源，外部推送的任务记录推送系统 |
| 子任务进度 | 系统自动统计 | 展示直接下级的「已完成数 / 总数」，无子任务时不展示 |
| 截止时间 | 由来源系统或创建人指定 | 影响列表排序，超期任务在列表中标记 |
| 完成时间 | 系统自动记录 | 人工办结时取办结时刻；因全部直接下级完成而自动办结时，取最后一个完成的下级的完成时间（逐级向上冒泡，规则见《AI 工作台 - 智能体伙伴与任务中心》4.5） |

  **差异说明（原型现状）：** ①原型中统计概览的四个数量目前按任务的紧急度近似计算，且点击标签不联动筛选，本需求按上述规则实现：统计口径取真实任务状态、与筛选联动；②原型列表按数据顺序排列，未实现优先级与截止时间排序；③原型未提供任务取消动作，故「已取消」统计恒为 0。④飞书待办同步状态列已按上述三态实现：状态由来源系统的同步开关派生（关闭「同步飞书待办」的业务系统，其任务显示未开启同步）、同步失败行提供「重试」且重试写入时间线、主任务与子任务各自判定不相互继承；未实现的部分是与飞书开放平台的真实调用，失败态与重试结果均为前端模拟，且转交时的待办撤回与重建未在原型中体现。⑤删除已在列表行内操作与任务详情标题区实现，按钮与二次确认均标明删除依据，确认文案列出级联子任务数、待办撤回、来源系统回告、不可恢复；子任务行不提供删除。需要说明的是，原型当前登录人罗紫函的角色是管理员，因此删除按钮对全部任务可见——**无删除权限的负例需要切换账号才能看到，原型不提供身份切换**。删除后从前端数据中移除，不计入统计，回告来源系统与飞书待办撤回为口径描述、原型不实际调用。⑥处理弹窗已去掉执行方选择，只填处理说明即办结；编辑弹窗已支持修改任务描述；任务详情已增加扩展字段区，默认为空、有值才展示。⑦时间范围已在筛选区实现（近 3 个月 / 全部时间），已完成与全部状态默认收窗且统计随之联动，未办结时选择器置灰并给出提示；原型内为便于观察窗口效果补充了两条 3 个月以外的历史已完成任务。

**需求说明：**

- **整体功能说明：**

  管理智能体的定时循环任务。与「我的任务」的区别是：我的任务是一次性的、有明确处理人的待办；智能体任务是按固定节奏反复执行的自动化任务，例如每天早上汇总昨日工单、每周一推送项目进度。使用者在这里创建定时任务、调整执行节奏、查看历史执行记录。

- **逻辑处理说明：**

  - 列表展示当前用户可见的定时任务，包含任务名称、执行智能体、执行节奏、下次执行时间、最近一次执行结果、启用状态。

  - 定时任务支持启用与停用。停用后不再触发，已产生的执行记录保留。
  - 每次执行生成一条执行记录，记录执行时间、执行结果（成功 / 失败）、执行输出摘要。执行失败时记录失败原因。
  - 定时任务的执行结果如果需要人工跟进，由智能体按任务类型配置创建对应任务，该任务进入指定处理人的「我的任务」。这是定时任务与任务列表的衔接点。
  - 执行记录支持按时间范围与执行结果筛选，默认展示最近 30 天。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 任务名称 | 必填，用于识别 | — |
| 执行智能体 | 必选，单选 | 可选范围为当前用户有权使用的智能体 |
| 执行节奏 | 必选 | 支持每天 / 每周 / 每月 + 具体时间点 |
| 执行内容 | 必填，自然语言描述 | 描述希望智能体每次执行时做什么 |
| 结果通知方式 | 可选 | 支持不通知 / 站内提示 / 推送到指定飞书群 |
| 启用状态 | 启用 / 停用，默认启用 | 停用后不再触发执行 |
| 下次执行时间 | 系统按执行节奏推算 | 停用时不展示 |
| 最近执行结果 | 系统记录 | 展示成功 / 失败与执行时间 |

#### 4.3 平台配置·任务配置·任务类型配置

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  维护任务类型的入口。任务类型是任务归集的基础：它决定一个任务归属哪个业务域、进入平台时必须带哪些信息。界面以业务域为一级、任务类型为二级的树形结构展示，用户在树上新增、编辑、停用类型。任务类型**不配置处理主体、不配置订阅智能体**——派单由业务系统定义，处理任务也不再选执行方。

  **配置不设审核环节，保存即生效。** 能否进入此页面、能否操作，由用户在「用户管理」中被授予的权限决定：需要有「平台配置 → 任务配置」功能权限才能看到入口，具体能维护哪些任务类型由「任务类型管理权限」的授权范围决定（见 4.5）。

- **逻辑处理说明：**

  **层级与编码**

  - 配置维护两级：一级是业务域（如服务一条链、项目空间、营销管理），二级是任务类型（如故障处理、异常投诉、主动运营、项目行动项、管理派单）。
  - 每个任务类型有唯一编码，编码格式为「业务域缩写 - 类型缩写」，例如服务一条链下的故障处理编码为 `SRV-FAULT`。编码创建后不可修改，因为外部系统按编码推送任务。
  - 用户只能看到并维护自己「任务类型管理权限」范围内的任务类型；范围外的类型不出现在树中。未授予任何类型时，页面为空态并提示联系管理员分配权限。
  - 任务在列表和详情中展示的第三段（细分场景）由创建任务的一方在创建时指定，不在此处配置，也不做取值约束。

  **必须参数**

  - 每个任务类型可以定义一组必须参数，表示该类型的任务进入平台时必须携带的信息，例如故障处理必须带设备编号与故障现象。
  - **每项必须参数由「参数名称 + 参数描述」两个字段组成，可配置多项。** 参数名称是外部系统推送时使用的键名，参数描述说明这个参数该填什么，供对接方与配置人对照，不参与校验。
  - 交互上按行编辑：每行一个参数，左侧填参数名称、右侧填参数描述，行尾提供删除；底部「+ 添加参数」追加新行。不设数量上限，也允许一项都不配（该类型对参数无要求）。
  - 参数名称在同一任务类型内不可重名。保存时校验：填了参数描述但参数名称为空的行不允许保存；两个字段都为空的行在保存时自动丢弃，不当作校验错误——用户点了添加又改主意的情况比填错更常见。
  - 之所以把描述与名称一起配置，是因为对接方拿到的只有一份参数清单，光有键名无法判断该传什么值，描述缺位时对接沟通只能靠口头补充。
  - 外部系统推送任务时缺少必须参数，平台拒绝接收并把缺失项回告来源系统。
  - 平台内部派生任务时缺少必须参数，任务仍然创建，但在任务详情中标记信息不完整，提示处理人补充。

  **不配置处理主体**

  - 任务类型上**不设处理主体字段**，平台不按任务类型派单。处理人由创建任务的一方在创建时指定：外部业务系统推任务时作为必须信息带入，平台内派生的任务由派生方指定。
  - 因此任务类型的调整不涉及"已分派任务要不要重新分派"的问题——分派规则不在平台侧，改任务类型不影响任何在途任务的归属。
  - 派单规则由业务系统定义。业务侧按自己的值班表、客户归属、组内分工决定推给谁，平台只校验处理人是否为平台内有效用户。处理人无效时拒绝建单并回告。

  **不配置订阅智能体**

  - 任务类型上**不设订阅智能体字段**。原有的「订阅智能体」配置随处理动作取消执行方选择一并去掉：处理任务只填处理说明即办结，平台不需要预先约定"这个类型能派给哪些智能体"。
  - 处理人需要智能体协助时，在对话中直接调用智能体，可用范围由智能体本身的可见性与授权决定，与任务类型无关。这样配置项少一处，可用智能体也不再受任务类型这层额外约束。

  **保存生效与启停**

  - 任务类型保存即生效，不经过备案或审核。新建保存后立即可被业务系统勾选、可接收任务。
  - 修改必须参数同样即时生效，作用于调整之后新产生的任务，不回溯已创建的任务。
  - 类型状态只有**启用中 / 已停用**两种，由有权限的用户直接切换，不存在中间的待审核态。
  - 只有启用中的任务类型才能被业务系统勾选推送。
  - 停用后不再接收新任务，已有任务不受影响，继续按正常流程处理与回写。停用需二次确认，确认弹窗提示该类型最近 7 天的新增任务量与在途任务数。
  - 停用的类型自动从各业务系统的获权范围中移除（见 4.4），并在业务对接配置界面提示。停用后可重新启用，重新启用不需要审核。
  - 关键属性的变更需要留痕：记录操作人、操作时间、变更前后的值，可在该类型下查看变更记录。取消审核不等于取消追溯。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 业务域 | 必选 | 一级分类，从已有业务域中选择 |
| 任务类型名称 | 必填 | 二级分类，同一业务域内不可重名 |
| 任务类型编码 | 必填，创建后不可修改 | 格式为「业务域缩写-类型缩写」，外部系统按此推送 |
| 必须参数 | 可选，可配置多项，按行增删 | 每项由**参数名称 + 参数描述**组成。参数名称是外部系统推送的键名，同类型内不可重名，用于校验推送任务的完整性；参数描述说明该参数填什么，供对接方对照，不参与校验 |
| 启用状态 | 有权限的用户直接切换 | 启用中 / 已停用。保存即生效，无审核态。停用后不接收新任务 |
| 变更记录 | 系统记录 | 操作人、操作时间、变更前后的值，用于追溯 |

  **差异说明（原型现状）：** 原型已按上述规则实现审核环节的移除——表头「备案」改为「状态」，取值只有启用中 / 已停用，行操作提供停用 / 启用直接切换；停用弹出二次确认并提示该类型最近 7 天新增任务量与在途任务数，确认后自动从各业务系统的获权范围中移除（见 4.4）；重新启用后提示需在业务对接配置中重新授权，不会自动恢复原有获权关系。新增保存后提示「保存即生效，可在业务对接配置中授权给业务系统」，编辑保存后提示「必须参数校验规则即时生效，变更已留痕」。原型已移除「权限主体（可见可处理）」列，与本节"不配置处理主体"的口径一致；本轮评审后「订阅智能体」列与新增 / 编辑弹窗中的订阅智能体多选一并移除。必须参数已改为按行配置的「参数名称 + 参数描述」，行尾可删、底部可「+ 添加参数」，列表列展示已配置的参数名称。尚未在原型中实现的部分：参数名称重名校验与空名校验为口径描述、原型未拦截；变更记录只有留痕提示，没有查看入口；确认弹窗中的 7 天新增量与在途数为示意数据。上述部分按本节规则实现。

**需求说明：**

- **整体功能说明：**

  维护外部业务系统对接关系的入口。一个外部系统要在平台创建任务，需要先在这里登记、配置对接参数、并明确它可以创建哪些类型的任务。界面以列表展示已登记的业务系统及其启用状态，点击「对接配置」进入配置弹窗调整参数与获权范围。

  **同样不设审核环节，保存即生效。** 入口可见性与可操作性由「平台配置 → 任务配置」功能权限控制。对接**只有启用 / 停用两态**，不设测试模式与多级对接状态。

- **逻辑处理说明：**

  **职责边界**

  - **业务侧实现具体任务流程** —— 一个任务在业务系统内部怎么产生、走什么审批、什么条件下升级派单，由业务系统自己决定，平台不介入。
  - **平台提供三类能力** —— 任务分类定义、主/关联任务创建、任务查询。业务系统通过这三类能力把自己的流程接到平台的任务体系上。
  - 这条边界决定了本配置项的作用：它不是配置业务流程，而是配置「哪个系统可以用平台的哪些能力、在什么范围内用」。

  **平台开放的三类能力**

  - **任务分类定义** — 业务系统可以读取平台的任务类型清单，据此知道自己能创建哪些类型、每种类型需要携带哪些必须参数。读取到的范围仅限该系统的获权类型。
  - **主/关联任务创建** — 业务系统可以创建主任务，也可以在已有主任务下创建关联的子任务。创建时需指定任务类型编码、任务标题、必须参数、处理人、以及业务系统内的单据编号。平台据此完成校验与建单，处理人由业务系统指定，平台不做二次分派。
  - **任务查询** — 业务系统可以查询自己创建的任务的当前状态与处理结果，用于在业务系统界面上回显进度。查询范围限于该系统自己创建的任务，查不到其他系统的任务。

  **对接参数**

  - 对接参数是该系统与平台之间的连接配置，由有权限的用户在配置弹窗中填写。不同系统需要的参数不同，按实际对接方式组合，常见的有四类：
    - **身份凭证** — 平台识别调用方身份的凭据，用于确认「这次调用确实来自这个已登记的系统」。
    - **回调地址** — 平台把任务状态变化通知回业务系统的接收地址。需要业务系统在自己界面上回显任务进度时必须配置。
    - **事件订阅** — 业务系统内部发生特定事件时自动触发平台建任务的约定，例如工单按规则升级后自动派单，不需要人工点击。
    - **数据同步约定** — 双方共享的主数据同步方式与频率，例如客户主数据每日凌晨同步一次，保证两边的客户信息一致。
    - **字段映射** — 业务系统的关键标识与平台任务字段的对应关系，例如商机编号、客户编号、负责人工号分别对应到平台任务的哪个信息位。映射关系决定了任务能否正确关联到平台内的客户与人员。
  - 对接参数变更后保存即替换生效，不设审核等待期。为避免改错导致对接中断，保存前提供「连通性校验」：按新参数试调用一次，校验不通过时给出失败原因并允许强制保存（强制保存需二次确认）。变更留痕，记录操作人与变更前后的值，出问题可回退到上一版参数。

  **获权任务类型**

  - 每个业务系统需要勾选它可以创建的任务类型。可勾选范围仅限**启用中**的任务类型，已停用的类型不出现在可选列表里。
  - **未获权的任务类型对该来源系统完全不可见** —— 不是调用时被拒绝，而是在任务分类定义的读取结果中就不返回。业务系统看不到自己没有权限的类型，避免误用。
  - 系统尝试创建获权范围外的任务类型时，平台拒绝创建，并把拒绝原因回告来源系统。
  - 已勾选的类型如果后续被停用，该系统的获权范围中自动移除，并在配置界面给出提示。
  - 修改获权范围保存即生效。缩小范围时提示该系统在被移除类型下的在途任务数，已创建的任务不受影响。

  **是否同步飞书待办**

  - 每个业务系统配置一个「同步飞书待办」开关，决定该系统推来的任务要不要为处理人生成飞书待办。
  - **按业务系统配置而不是全局配置**，原因是不同来源的任务对处理人的打扰程度不同：售后工单这类要求即时响应的，进飞书待办才能保证不漏；主动运营、续费提醒这类批量推入、按节奏处理的，进飞书待办会把处理人的待办列表淹掉，反而降低待办的可信度。全局一个开关无法区分这两类。
  - 因此**同一个处理人可能同时持有同步与不同步的任务**：他的飞书待办里只有需要即时响应的那部分，完整的任务视图在平台的「我的任务」里。列表的同步状态列就是让他知道哪些任务不会在飞书里提醒自己（见 4.1）。
  - 开关的生效范围是**后续新建的任务**：
    - 由关改为开 — 后续该系统推来的任务开始生成飞书待办，存量任务不追溯补建。存量任务已经在平台内被看到过，补建会产生一批处理人不预期的待办。
    - 由开改为关 — 后续该系统推来的任务不再进飞书；**已生成的飞书待办保持不变，不做回收**。已经出现在待办里的任务，处理人可能已经安排了处理计划，撤回会造成任务丢失的错觉。
  - 切换开关保存后给出对应提示，说明生效范围与存量待办的处理方式，避免操作人误以为是全量生效。
  - 平台内派生的任务（群聊识别、skill 产出、智能体创建、页面手动创建）不隶属任何外部系统，**默认同步飞书待办**，不受本开关影响。
  - 待办创建失败时，任务本身照常建立、正常进入处理人列表，不因待办失败而阻塞建单；失败状态与重试入口在「我的任务」呈现（见 4.1）。

  **启用与停用**

  - 对接只有两态：**启用中**（可调用三类能力、正式接收任务）与**已停用**（不能再调用任何能力）。原有的「测试模式」与四态「对接状态」一并取消。
  - 取消的原因是这两项的成本高于收益：测试任务需要在任务列表、统计、待办、回写各处做一套隔离逻辑，而联调本身在测试环境完成即可，不需要在生产配置里留一个长期开关；四态中的「待对接」也只是"参数没填完"的另一种说法，配置弹窗本身就会拦住不完整的保存，不必再用一个状态复述一遍。
  - 新增业务系统保存即为启用中。配置不完整（对接参数为空或未获权任何任务类型）时不允许保存，在弹窗内提示补齐，而不是保存成一个不可用的状态。
  - 停用一个业务系统后，该系统不能再创建任务，也不能查询任务。已创建的任务不受影响，继续按正常流程处理与回写。
  - 停用需要二次确认，确认弹窗中提示该系统最近 7 天的建任务量与在途任务数，让操作人判断影响面。
  - 停用后可以重新启用，重新启用不需要审核，恢复到停用前的参数与获权范围。停用期间被停用的任务类型不会自动恢复获权，需在配置弹窗中重新勾选。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 业务系统名称 | 必填 | 例如 case 单系统、客成系统、CRM、天润客服 |
| 系统标识 | 必填，创建后不可修改 | 平台识别调用来源的依据，与身份凭证配套使用 |
| 对接负责人 | 必填 | 对接异常时的联系人，回写失败等异常通知此人 |
| 对接参数 | 必填 | 按实际对接方式填写身份凭证 / 回调地址 / 事件订阅 / 数据同步约定 / 字段映射，具体约定见第四章 |
| 可调用创建的任务类型 | 必选，可多选 | 仅可选择启用中的任务类型，未勾选的类型对该系统不可见 |
| 同步飞书待办 | 开 / 关，默认开 | 该系统推来的任务是否为处理人生成飞书待办。仅对后续新建任务生效，关闭时已生成的待办不回收 |
| 启用状态 | 有权限的用户直接切换，新增保存即启用 | 启用中 / 已停用两态。停用后拒收新任务，已有任务不受影响 |
| 最近建任务时间 | 系统记录 | 用于判断对接是否正常工作，长时间无调用时在列表中提示 |
| 在途任务数 | 系统统计 | 该系统创建且尚未办结的任务数量，停用前的影响面判断依据 |

  **差异说明（原型现状）：** 原型已按上述规则实现的部分——本轮评审后「对接状态」与「测试模式」两列及行内测试模式开关一并移除，列表只保留启用中 / 已停用；可勾选类型严格过滤为启用中的类型，且勾选项与存量取值统一为「业务域 › 任务类型」全名，不再出现存量已获权但显示未勾选的情况；未获权任何类型的行显示空态文案；修改对接参数时先做一次连通性校验，校验不通过弹出二次确认可强制保存，强制保存后行操作出现「参数回退」按钮，可回退到上一版参数；停用需二次确认并说明在途任务继续流转、参数与获权范围保留。尚未在原型中实现的部分：对接参数仍为单个自由文本框，未拆分为身份凭证 / 回调地址 / 事件订阅 / 数据同步约定 / 字段映射五项；系统标识、对接负责人、最近建任务时间、在途任务数四个字段未在界面呈现，因此停用确认弹窗中未给出 7 天建任务量与在途任务数；缩小获权范围时未提示被移除类型下的在途任务数；连通性校验为前端模拟。「同步飞书待办」已在列表新增一列（已开启 / 未开启）并在配置弹窗提供勾选项，保存后按开关的变化方向给出生效范围提示；原型中客成系统为关闭态，用于呈现「未开启同步」的任务；未实现的部分是与飞书开放平台的真实对接，开关只驱动列表状态展示。上述部分按本节规则实现。

#### 4.5 用户管理·功能权限与数据管理权限

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  用户管理是权限的唯一配置入口，位于管理中心。**平台侧各类配置能力的管控方式统一为「基于用户权限控制可见页面与可操作功能」，不使用审核流程。** 一个用户能做什么，取决于两组授权：

  - **功能权限** — 决定他能看到哪些页面、能操作哪些功能。树形结构，父节点为页面、子节点为该页面内的敏感功能。
  - **数据管理权限** — 决定他能管理哪些具体对象。按对象类型分组多选，包括智能体、知识库、项目空间、技能库、以及本次新增的任务类型。

  用户管理本身也是一个受控功能：只有被授予「用户管理」功能权限的人才能进入。

- **逻辑处理说明：**

  **用户列表**

  - 列表字段：用户 ID、姓名、登录账号、邮箱、角色、智能体数、操作。
  - 支持按角色筛选（默认「全部」）与按姓名搜索，配合查询、重置按钮。
  - 行操作：重置密码、编辑、禁用 / 启用。重置密码需二次确认，初始密码发送到该用户邮箱。
  - 禁用需二次确认，确认弹窗说明影响面：禁用后该账号不能登录，但名下智能体的定时任务继续运行、已分派给他的任务不自动转出，需由有权限的人转交。已禁用的用户可重新启用。
  - 智能体数为该用户被授权管理的智能体数量，点击可查看明细。
  - 支持新增用户，字段与编辑一致。

  **功能权限树（本次新增节点）**

  - 现有节点：会话记录（含子项 会话导出）、用户管理、知识库管理（含子项 公司知识仓库创建）、技能库（含子项 看板配置）、任务执行（含子项 指定用户）、平台配置（含子项 模型配置）。
  - **本次新增一级节点「平台配置」，其下新增子节点「任务配置」**：勾选后该用户可见并可操作 平台配置 → 任务配置（任务类型配置 + 业务对接配置）。未勾选时左侧导航不出现「平台配置」入口。
  - 父子节点联动：勾选子节点自动勾选父节点（父节点代表页面可见，子节点代表页面内的敏感操作）；取消父节点时其下子节点一并取消。
  - 「任务执行 → 指定用户」的含义是：可以把任务指派/转交给指定的其他用户，未勾选时只能处理归属自己的任务，不能指派他人。

  **任务类型管理权限（本次新增数据权限）**

  - 与智能体管理权限、知识库管理权限、项目空间管理权限、技能库管理权限并列，同属数据管理权限一组。因为任务类型是两级结构，授权形式不用多选标签框，改为三选一的授权模式 + 对应的多选项：
    - **不授权** — 默认值。该用户即使有「任务配置」功能权限，进入页面后配置树为空。
    - **按业务域授权** — 勾选一个或多个业务域，该业务域下的全部任务类型都可维护，**且该业务域后续新增的任务类型自动纳入授权范围**，不需要再次配置。适合业务域的负责人。
    - **按单个类型授权** — 勾选具体的任务类型，只可维护勾中的类型。可选项只列启用中的类型，已停用的类型不出现在可选列表。适合只负责个别场景的人。
  - 切换授权模式时清空另一种模式下已勾选的项，避免出现两种粒度并存导致范围歧义。列表页的「任务类型管理权限」以「业务域：… / 指定类型：… / 未授权」的形式回显当前授权。
  - 该权限决定用户在任务类型配置树中能看到、能维护哪些类型；范围外的类型不出现在树里。
  - 有「任务配置」功能权限但未分配任何任务类型管理权限时，页面可进入但树为空态，提示联系管理员分配范围。业务对接配置的获权类型勾选范围同样收敛到该用户被授权的类型。
  - 该权限**同时是任务删除权的来源之一**：授权范围覆盖某个任务的类型时，该用户可删除这个类型下的任务（见 4.1「任务删除」）。按业务域授权时，该域下所有类型的任务都在删除范围内。

  **管理员角色与删除权**

  - 不新增「超级管理员」角色，**由现有「管理员」角色承担超级管理口径**：管理员可删除任何任务，不受任务类型授权范围限制。理由是平台的角色模型已有管理员，再加一层超管会让两者的边界难以说清，也增加授权时的判断成本。
  - 因此任务删除权的三个来源分别对应：创建人（任务归属）、管理员（角色）、任务类型管理权限（数据范围）。三者是并集关系，满足任一即可删除。

  **权限生效与校验**

  - 权限变更保存后即时生效，用户端下次进入页面按新权限渲染，不需要重新登录。
  - 权限控制必须同时在**前端渲染**与**接口校验**两层落地：前端不渲染无权限的入口与按钮，接口对每次操作重新校验权限，避免绕过界面直接调用。
  - 越权访问的处理：直接访问无权限页面时返回无权限提示页，不返回空白页也不静默跳转，让用户知道是权限问题而不是功能故障。
  - 权限变更留痕：记录操作人、被操作人、变更的权限项与变更时间。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 角色 | 必选 | 如 管理员 / 普通用户。角色是权限的默认模板，新增用户时按角色带出默认权限，可在此基础上逐项调整 |
| 姓名 | 必填，10 字以内 | 展示名，任务处理人、转交接收人等场景按此显示 |
| 登录账号 | 必填，20 字以内，创建后不可修改 | 登录凭据，全局唯一 |
| 邮箱 | 可选 | 通知触达地址 |
| 功能权限选择 | 树形多选 | 控制可见页面与可操作功能。本次新增 平台配置 → 任务配置 |
| 智能体管理权限 | 多选 | 可管理的智能体范围 |
| 知识库管理权限 | 多选 | 可管理的知识库范围 |
| 项目空间管理权限 | 多选 | 可管理的项目空间范围 |
| 技能库管理权限 | 多选，按技能类别添加 | 可管理的技能类别范围，看板配置权限归入此项 |
| 任务类型管理权限 | 本次新增，三选一模式 + 多选项 | 不授权 / 按业务域授权（含该域后续新增类型）/ 按单个类型授权（仅可选启用中的类型），决定任务类型配置树的可见与可编辑范围 |

  **差异说明（原型现状）：** 原型已实现的部分——智能体平台左侧导航新增「用户管理」独立页面，包含角色筛选 + 姓名 / 账号关键词搜索、查询与重置、用户列表（用户 ID、姓名、登录账号、邮箱、角色、智能体数、操作）以及重置密码 / 编辑 / 禁用·启用行操作；重置密码与禁用均为二次确认，禁用提示「禁用后不可登录，名下 N 个智能体的定时任务继续运行」；新增 / 编辑用户弹窗实现功能权限树（六个一级节点，父子联动：勾子自动勾父、取消父清空子）与任务类型管理权限的三种授权模式；登录账号在编辑态只读、新增态做重名校验；保存后按是否具备「任务配置」权限与任务类型授权范围给出差异化提示。尚未在原型中实现的部分：智能体 / 知识库 / 项目空间 / 技能库四项数据管理权限为「已选 N · 修改」入口，点击仅弹提示，未实现具体对象选择器；智能体数不可点击查看明细；分页为示意控件；用户数据为前端内存数据，刷新即重置；各配置页面本身未按权限做入口隐藏与越权拦截，任何进入的用户都可操作全部配置；任务删除权虽已按「创建人 / 管理员 / 任务类型管理权限」三者取并集判定，但原型当前登录人是管理员，实际总是命中管理员这一条，按业务域或按类型授权的判定分支未被真实触发。上述部分按本节规则实现，其中前端渲染与接口校验双层落地为必须项。

## 四、关联系统处理

### 4.1 对接总体约定

**分工原则**

| 职责 | 承担方 | 说明 |
|------|--------|------|
| 具体任务流程实现 | 业务系统 | 任务在业务系统内部如何产生、审批、升级，平台不介入 |
| 任务分类定义 | 平台 | 提供任务类型清单与每类的必须参数要求 |
| 主/关联任务创建 | 平台 | 接收业务系统的建任务请求，完成校验与建单 |
| 派单（决定处理人） | 业务系统 | 按业务侧的值班、客户归属、组内分工决定推给谁，建任务时带上处理人 |
| 任务查询 | 平台 | 提供任务状态与处理结果的查询 |
| 任务处理 | 平台 | 处理人在平台完成处理，结果回写业务系统 |

**能力调用的前置条件**

任一能力被调用时，平台先校验调用方：系统标识已登记、身份凭证有效、该系统处于**启用中**。不满足即拒绝，不进入后续处理。

### 4.2 三类能力的调用约定

**能力一：任务分类定义**

- 业务系统读取自己可创建的任务类型清单。
- 返回内容包含：任务类型编码、类型名称、所属业务域、该类型的必须参数清单及每项参数的说明。
- **返回范围严格限定为该系统的获权类型**。未获权类型不出现在返回结果中，业务系统无法感知其存在。
- 业务系统应在建任务前读取此清单，据此组装参数，避免因缺参数被拒。
- 平台侧任务类型的必须参数发生变更时，通过回调地址通知已获权该类型的所有业务系统。

**能力二：主/关联任务创建**

- 创建主任务时需提供：任务类型编码、任务标题、任务描述、业务系统内的单据编号、**处理人**、该类型要求的全部必须参数。可选提供优先级与截止时间，未提供时平台按任务类型的默认值填充。
- **处理人是必须项。** 平台不提供按任务类型的默认分派，派单规则由业务系统定义；未带处理人或处理人不是平台内有效用户时，平台拒绝建单并回告。
- 创建关联任务（子任务）时需额外提供所属主任务的标识与该子任务的处理人。
- **业务系统内的单据编号是必须项**，平台据此生成任务上展示的「关联业务系统编号」，供处理人回到来源系统核对。
- 平台按顺序做三层校验，任一层不通过即拒绝创建并回告原因：

  1. **来源校验** — 系统标识已登记、该系统处于启用中
  2. **类型校验** — 任务类型编码在该系统的获权范围内、且该类型为启用中状态
  3. **参数校验** — 携带了该任务类型配置的全部必须参数，且处理人为平台内有效用户

- 拒绝时回告内容需明确到具体原因，参数缺失时逐项列出缺哪些参数，便于业务侧自查。
- 校验通过后，平台按业务系统指定的处理人建单，任务进入该处理人的「我的任务」，并返回平台任务编号给业务系统留存。
- 同一单据编号重复创建同一类型的任务时，平台不重复建单，返回已存在的任务编号，避免业务系统重试导致任务重复。

**能力三：任务查询**

- 业务系统可按平台任务编号或自己的单据编号查询任务。
- 返回内容包含：任务当前状态、处理人、完成时间、处理说明；有子任务时包含各子任务的状态与完成情况。
- **查询范围限于该系统自己创建的任务**，查不到其他系统创建的任务，也查不到平台内部派生的任务。
- 查询能力用于业务系统界面回显进度。需要实时感知状态变化的场景应配置回调地址，由平台主动通知，不建议轮询。

### 4.3 对接参数说明

| 参数类别 | 作用 | 必要性 |
|----------|------|--------|
| 身份凭证 | 平台确认调用方身份 | 必须，所有对接方式都需要 |
| 回调地址 | 平台主动把任务状态变化通知业务系统 | 需要在业务系统回显任务进度时必须 |
| 事件订阅 | 业务系统内部事件自动触发平台建任务 | 需要自动派单时配置，人工触发建任务时不需要 |
| 数据同步约定 | 双方主数据（客户、人员）的同步方式与频率 | 任务需关联平台内客户或人员时必须 |
| 字段映射 | 业务系统关键标识与平台任务信息位的对应关系 | 任务需关联平台内客户、商机、负责人时必须 |

字段映射的典型内容：业务系统的客户编号对应平台的客户主数据标识、商机编号对应平台的商机记录、负责人工号对应平台的用户。映射不完整会导致任务创建成功但关联信息缺失，平台在任务详情中标记信息不完整并提示处理人。

### 4.4 处理结果回写

平台通过业务系统配置的回调地址主动通知状态变化，不需要业务系统轮询。

**回写时机**

| 触发动作 | 回写内容 |
|----------|----------|
| 任务办结 | 最终状态、处理人、完成时间、处理说明 |
| 任务转交 | 新处理人 |
| 任务重新打开 | 状态变更为待办，清空完成时间，业务系统据此调整自身单据状态 |
| 子任务状态变化 | 该子任务的状态、完成时间与其层级路径 |
| 节点因下级全部完成而自动办结 | 完成时间取**最后一个完成的直接下级**的完成时间，不取系统触发办结的时刻。自动办结逐级向上冒泡时，每一级的状态变化都回写 |
| 节点提前人工办结 | 该节点完成时间，以及被逐级关闭的**全部层级**下级清单：状态为「已完成（随上级关闭）」，完成时间取上级的办结时间 |
| 已办结节点被重新打开 | 该节点及因冒泡而办结的各级上级一并回写为待办，并清空各自完成时间 |
| 任务被删除 | 任务已删除、删除时间、删除人、连带删除的下级任务清单。业务系统据此关闭或标记自己的单据，避免单据仍在等待平台结果 |

**异常处理**

- 回写失败时进入重试。重试期间任务在平台侧的状态已经生效，不因回写失败而回滚。
- 连续重试失败后，在任务详情中标记「结果回写失败」，处理人可以看到结果未同步到来源系统，同时通知该业务系统的对接负责人。
- 标记为回写失败的任务提供手动重试入口，供对接负责人排查后重新触发。

### 4.6 新系统接入流程

```
业务侧提出接入需求
 → 双方在测试环境确认对接方式与参数要求，业务侧调用任务分类定义、试建任务验证校验通过
 → 有「任务配置」权限的用户在业务对接配置中登记系统：填写系统名称、系统标识、对接负责人、
    对接参数，勾选获权任务类型（配置不完整不允许保存）
 → 保存即生效 → 启用中，正式接收任务
 → 需要暂停接入时停用，恢复时再启用
```

联调在测试环境完成，生产侧不设测试模式，因此登记生产对接前应先完成验证。后续调整对接参数或获权范围时保存即替换生效，不设审核等待期。参数变更保存前可做连通性校验，变更留痕并支持回退到上一版参数。

### 4.7 与 AI 工作台的关系

智能体平台的「任务执行」与 AI 工作台的「任务中心」共用同一份任务数据与同一套处理逻辑。差异仅在于呈现形态：平台侧是面向处理人的表格化列表，适合批量查看与筛选；工作台侧是左右两区布局（左列表、右详情，处理时间线在详情内），与智能体对话、项目空间衔接。

两端的列表模型一致，都按**处理人视角条目制拉平**：归属自己的主任务与归属自己的子任务（任意层级）各占一条，子任务不作为主任务的缩进附属项。工作台侧另有平台侧不具备的展示：详情中的只读上级任务卡片、仅列直接下级的子任务处理节点、以及每个子任务独立的处理记录。

任何一端的处理动作（办结、转交、重新打开、任意层级的子任务推进与逐级冒泡办结）在另一端即时可见，不存在两端状态不一致的中间态。工作台侧的详细交互规则见《AI 工作台 - 智能体伙伴与任务中心》。
