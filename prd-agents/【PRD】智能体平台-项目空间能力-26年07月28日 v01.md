## 一、概述

### 1.1 需求背景

KA 项目流程变革要求项目组在**统一上下文**上工作：项目信息不再散落在群聊、文档、CRM 各处，智能体与人基于同一份项目上下文协作，实现「AI 输出初稿 → 人确认/修正 → 沉淀知识库」的闭环。

智能体平台现有公司知识仓库、客户知识空间与飞书群智能体能力，但缺少**项目空间**这一承上启下的载体：它向上为 AI 工作台提供项目上下文与应用入口，向下组织客户、知识、成员与任务，并为 **KA 主理智能体**提供能力挂载的边界。本需求定义智能体平台侧的项目空间能力，以及挂载其上的 KA 试点 skill 组。

| 序号 | 需求项 | 优先级 | 说明 |
|------|--------|--------|------|

## 三、需求正文

### 1. 产品定义

**项目空间**是智能体平台上围绕一个客户项目的能力载体：它关联客户与知识、维护项目统一上下文、定义成员授权、承载任务清单，并为 KA 主理智能体提供能力挂载的边界。

**KA 主理智能体**是平台上唯一的 KA 项目主理智能体。每个项目群里的都是同一个主理智能体，不同的是它**按群挂载的项目空间**——群与项目空间绑定后，主理智能体在该群中的一切理解、产出与跟进都基于所挂载的项目空间进行，各项目数据相互隔离。

面向角色：销售/售前、需求调研/解决方案、项目经理、交付/客成、平台运营。

### 2. 处理流程

**项目建立**：
```
确认合作 → 基于模板创建项目空间（关联客户/绑定群/成员授权）
→ KA 主理智能体自动入群并挂载该项目空间与 skill 组合
→ 输出项目初始化摘要 → 项目经理确认后启动
```

**日常运行（统一上下文维护）**：
```
群消息/文档变更/CRM 阶段变更 → 智能体持续接收并理解
→ 识别影响项目上下文的变更 → 生成更新建议
→ 项目经理确认 → 写入项目摘要（版本可追溯）
```

**方案产出（skill 调用）**：
```
用户在工作台或群内发起 → 智能体基于项目统一上下文 + 知识库执行 skill
→ 输出初稿（带引用溯源）→ 人审核/迭代 → 定稿沉淀
（项目空间 + 公司知识仓库 + 客户知识空间）
```

### 3. 产品信息结构图

```
资源库
 ├── 自定义知识库（已有）
 ├── 公司知识仓库（已有）
 ├── 客户知识空间（已有）
 └── 项目空间（本需求）
      ├── 关联客户 → 自动带入客户信息与客户知识空间
      ├── 项目摘要 → 项目目标/阶段/关键结论/分工/风险概况
      ├── 用户授权 → 角色职责定义 → 关联飞书用户 → 权限校验
      ├── 任务清单 → 待办（负责人/截止/状态/来源）
      └── 经营看板（数据支撑，呈现见 AI 工作台 PRD）

KA 主理智能体（平台唯一，按群挂载项目空间）
 ├── 挂载 skill：调研方案生成 / 需求解决方案 / POC 报告 / 任务拆解 / 每周分析总结 / 平台标准 skill
 ├── 关联：公司知识仓库 + 客户知识空间 + 项目空间（按群定位挂载）
 └── 群协同：接收绑定群全部消息 → 自主选择性响应
```

### 4. 原型及需求说明

#### 4.1 项目空间 — 创建与关联客户

**原型截图：** [待补充原型截图]

**需求说明：**

- **整体功能说明：**
  平台运营或项目经理在智能体平台上基于「KA 项目」模板创建项目空间，关联客户、绑定飞书群、添加成员。创建完成后，KA 主理智能体自动入群并将本项目空间挂载到该群，输出项目初始化摘要。

- **逻辑处理说明：**
  - 关联客户后，自动带入：客户基本信息（行业、合同金额、营销阶段 CR1-CR7）、历史对接记录、客户知识空间内容
  - 自动从公司知识仓库检索同类项目最佳实践，关联到本项目知识视图
  - 绑定飞书群后，KA 主理智能体自动入群并开始接收群消息；该群中智能体的上下文即为本项目空间
  - 项目初始化摘要包含：客户背景、同类项目参考、建议分工、初始待办，**项目经理确认后项目正式启动**

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 项目名称 | 文本输入 | 如「远航物流 · 智能调度平台项目」 |
| 关联客户 | 从已有客户中选择 | 绑定后自动带入客户信息 |
| 项目阶段 | 下拉选择 | 对应营销阶段 CR1-CR7 |
| 项目目标 | 文本输入 | 一句话描述项目要达成什么 |
| 绑定飞书群 | 搜索并选择群聊 | 绑定后智能体自动入群 |
| 项目模板 | 模板选择 | KA 攻坚 / 签约交付 / 客户运营预设 |

#### 4.2 项目空间 — 项目摘要与自动更新

**原型截图：** [待补充原型截图]

**需求说明：**

- **整体功能说明：**
  项目摘要是项目统一上下文的核心：项目目标、当前阶段、关键结论、分工、风险概况，一页看清项目全貌。摘要由 AI 创建时生成初稿，运行中自动维护更新，用户可从摘要逐层查看渐进明细文档。

- **逻辑处理说明：**
  - 智能体持续接收**绑定群全部消息**、项目文档变更、CRM 阶段变更，识别影响项目上下文的变更（关键决策、需求变更、阶段推进、风险变化）
  - 识别到变更后生成**更新建议**（变更内容 + 依据来源），推送给项目经理
  - **项目经理确认后才写入**摘要；每次更新保留历史版本，可回溯、可回滚
  - 摘要更新 skill 使用平台默认配置，项目级可修改（如哪些变更类型需要确认、确认人是谁）
  - 摘要中的每项结论支持**渐进明细查看**：点击可钻取到对应的纪要、报告、方案版本等原始文档

---

#### 4.3 项目空间 — 用户授权

**原型截图：** [待补充原型截图]

**需求说明：**

- **整体功能说明：**
  项目负责人定义项目成员的角色与职责，关联飞书用户。授权结果驱动三处行为：项目空间可见范围、待办按角色指派、智能体产出确认人路由。

- **逻辑处理说明：**
  - 角色模板按项目类型预置（销售负责人/售前架构师/项目经理/交付工程师/客户成功经理等），可增删
  - 基于用户授权校验项目空间查看权限：项目成员可读写，非成员上级只读，无关人员不可见
  - 数据按客户维度隔离，与平台既有权限体系一致
  - 待办支持按角色指派（如「售前架构师」），系统自动匹配项目成员
  - 智能体产出需要人工确认时（如方案定稿、摘要更新），按职责路由到对应确认人

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 成员 | 按飞书组织选择 | 至少指定一名项目负责人 |
| 角色 | 从角色模板选择 | 决定权限与确认路由 |
| 职责说明 | 文本输入（选填） | 如「负责 TMS 对接方案」 |

---

#### 4.4 项目空间 — 任务清单

**需求说明：**

- **整体功能说明：**
  项目待办的统一清单，展示负责人、优先级、截止时间、状态与来源。

- **逻辑处理说明：**
  - 创建来源：① 群智能体从群聊识别任务分派；② skill 产出附带的结构化待办（经任务拆解 skill 人工确认）；③ 人工创建
  - 状态流转：待处理 → 进行中 → 完成；任一阶段可标记阻塞（需填原因）
  - **关联飞书待办跟进**：任务清单中的待办同步生成飞书待办，责任人可在飞书待办中直接查看、完成、转交，处理结果双向同步回项目任务清单
  - 智能体可主动查询飞书待办的执行状态（如临近截止未处理、已逾期），据此执行跟进提醒与状态回写（接入方式见第四章附录）
  - 提醒与升级沿用群智能体既有机制（早报提醒、到期前提醒、逾期分级升级）
  - 详细规则见《[prd]项目空间与飞书群智能体-26年06月28日 v01》，本需求不重复定义

#### 4.5 KA 主理智能体 — 项目空间挂载与配置

**原型截图：** [待补充原型截图]

**需求说明：**

- **整体功能说明：**
  平台存在唯一的 KA 主理智能体，服务所有 KA 项目群。项目创建并绑定群后，主理智能体自动将该项目空间挂载到对应群；项目负责人在项目空间设置中调整本项目挂载的 skill 组合与行为参数。

- **逻辑处理说明：**
  - **一智能体多项目**：主理智能体同时存在于多个项目群，通过群定位挂载的项目空间——在某群中接收消息、回答问题、产出内容时，仅使用该群所挂载项目空间的上下文与知识，各项目数据相互隔离
  - 挂载的默认 skill 组合：试点 skill 组（4.7-4.12）+ 平台标准 skill（文档处理、数据分析等），项目级可增删
  - 可修改的项目级配置：项目摘要更新 skill（确认范围/确认人）、群智能体行为参数（沿用既有配置体系）、skill 挂载组合
  - 不同项目模板对应不同预设：KA 攻坚（高频提醒）、签约交付（标准提醒）、客户运营（低频提醒）
  - 修改即时生效，所有智能体操作可回溯、可撤销

#### 4.6 群协同 — 全量消息接收与选择性响应

**需求说明：**

- **整体功能说明：**
  项目组成员日常仍在飞书群中协同工作。KA 主理智能体作为群成员**接收全部群消息**（无需被 @ 也在持续理解项目进展），基于该群挂载的项目空间理解上下文，并**自主判断何时响应、何时保持沉默**。

- **逻辑处理说明：**

| 智能体行为 | 触发场景 | 响应方式 |
|---|---|---|
| 主动响应 | 识别到任务分派/承诺确认、关键决策或风险、能直接回答的项目问题、讨论结论需要落锤 | 群内推送卡片或回复；把握不足时先推候选卡片等人确认 |
| 静默处理 | 项目相关的背景讨论但无需即时动作 | 仅作为上下文沉淀，不打扰群聊 |
| 完全忽略 | 闲聊等与项目无关内容 | 不处理 |
| 定时行为 | 每日早报、逾期提醒、群置顶摘要更新 | 按配置时间执行（免打扰时段除外） |

  - 群内 @智能体 的问答自动定位到本项目上下文回答，引用来源（消息时间+发言人）便于回溯
  - 消息合并、意图分类、把握度判断、免打扰等底层机制沿用《[prd]项目空间与飞书群智能体-26年06月28日 v01》已定义规则

#### 4.7 调研方案生成 skill

**原型截图：** 见试点原型「需求调研」视图

**需求说明：**

- **整体功能说明：**
  用户将客户访谈纪要（飞书文档/录音转写）导入，智能体提取结构化需求，关联历史同类项目，生成需求调研报告初稿。

- **逻辑处理说明：**
  - 从纪要中逐条提取需求：业务诉求/量化目标/性能约束/集成约束/预算约束等，**每条附原文引用位置**
  - 自动关联公司知识仓库中的同类项目（如「顺捷物流智能调度」），标注匹配度
  - 人审核逐条处理：**接受 / 修改 / 驳回**；驳回项回流重新提取
  - 审核完成后生成需求调研报告初稿，人确认定稿
  - 修正内容结构化记录（改了哪条、改成什么），用于每周提示词迭代
  - 定稿自动沉淀：项目空间 + 客户知识空间

---

#### 4.8 需求解决方案 skill

**原型截图：** 见试点原型「方案输出」视图

**需求说明：**

- **整体功能说明：**
  基于已确认的需求与公司方案库，智能体推荐方案框架与类似案例，生成一页纸方案初稿，支持人工迭代直至定稿。

- **逻辑处理说明：**
  - 方案框架按已确认需求逐条映射推荐，类似案例给出匹配度与知识库引用溯源
  - 一页纸方案支持版本迭代（目标 ≤3 轮）：每轮合并人工修正意见生成新版本，并输出**本轮修正点摘要与修正率**
  - 定稿必须人工确认；定稿后沉淀：项目空间 + 公司知识仓库（走入库流程，审核后发布）+ 客户知识空间
  - 方案定稿后可触发任务拆解 skill，生成交付行动项

---

#### 4.9 POC 报告 skill

**需求说明：**

- **整体功能说明：**
  POC 验证完成后，智能体基于 POC 执行数据与方案目标，自动生成 POC 验证报告，供客户内部立项使用。

- **逻辑处理说明：**
  - 报告围绕方案中承诺的量化目标逐项验证（如响应时长、成本降低比例、峰值稳定性）
  - 初稿由交付/客成确认后输出正式版
  - 报告沉淀至项目空间，并可选同步客户知识空间

---

#### 4.10 任务拆解 skill

**需求说明：**

- **整体功能说明：**
  智能体从方案、报告、群讨论中拆解行动项，**生成飞书待办**，人工确认后下发到责任人。

- **逻辑处理说明：**
  - 拆解结果包含：事项、建议负责人（按角色匹配）、建议截止时间、优先级
  - **必须经人工确认**后才正式下发；确认时可修改负责人与时间
  - 下发后进入项目任务清单，纳入统一提醒与升级机制
  - 待办支持转交，转交记录保留

---

#### 4.11 每周分析总结 skill

**需求说明：**

- **整体功能说明：**
  每周自动输出项目周报：本周进展、风险、下周计划，以及 AI 产出修正点复盘。

- **逻辑处理说明：**
  - 数据来源：项目空间任务清单、关键事件、里程碑、skill 产出修正记录
  - 周报自动推送项目群；修正点复盘供项目组每周复盘会使用
  - 里程碑节点自动检查交付物完整性，缺失时提醒项目经理确认

## 四、关联系统处理

> 本章为技术附录，描述与现有系统的集成，供开发评审使用。

### 4.1 与现有平台能力的关系

| 现有能力 | 集成方式 |
|---|---|
| 客户知识空间 | 项目空间绑定客户后读取；重大决策/里程碑选择性回写，日常待办不同步 |
| 公司知识仓库 | skill 检索走既有检索装配链路（权限过滤→召回→重排→引用溯源）；方案定稿走入库流水线 |
| 飞书群智能体 | 消息接入、意图分类、定时任务、配置体系整体复用，本需求仅扩展项目级配置与摘要更新 skill |
| 智能体执行环境 | KA 主理智能体复用既有执行与通知通道，不另建 |
| 飞书待办 | 任务清单待办双向同步飞书待办；智能体通过飞书 CLI 查询待办状态并执行跟进处理（见 4.4） |

### 4.2 数据隔离与权限

- 项目空间数据按客户维度隔离；用户授权校验与平台既有权限体系一致
- 智能体仅读取绑定群的对话，不保存原始群消息，仅保存结构化提取结果

### 4.3 与 AI 工作台的衔接

- 项目空间、项目摘要、任务清单、skill 产出通过平台能力开放给 AI 工作台呈现（见《[prd]AI工作台-项目空间与客户经营看板-26年07月28日 v01》）
- 工作台侧的 gitlab 云端提交同步作用于项目文档产出，不影响平台侧数据权威源

### 4.4 飞书待办集成（CLI 接入）

- 任务清单待办与飞书待办建立映射：创建/完成/转交/逾期状态双向同步
- 智能体通过飞书 CLI 提供的待办查询与处理能力执行：按项目/负责人查询待办执行状态、识别临近截止与逾期未处理项、回写跟进结果
- 查询与处理范围限于项目空间授权成员名下的相关待办，遵循飞书侧权限约束
