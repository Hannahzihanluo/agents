## 一、概述

### 1.1 需求背景

目前用户的待办散落在各处：项目群里的口头承诺、飞书待办、CRM/客服等业务系统的工单，以及智能体产出方案后拆解的行动项，彼此不通，靠人肉对齐。项目空间试点中已验证「标准任务实体 + 飞书同步 + 智能体跟进」的价值，本需求将其升级为**平台级通用任务模块**：所有来源的任务进入同一份任务清单，智能体统一跟进，用户在工作台一个入口完成查询、处理与催办。

### 1.2 需求清单

| 序号 | 需求项 | 优先级 | 说明 |
|------|--------|--------|------|
| 1 | 标准任务实体与统一任务列表 | P0 | 全平台任务一份实体；仅区分「来源」与「是否关联项目空间」两个维度 |
| 2 | 工作台对话查询与就地操作 | P0 | 对话内任务卡片，完成/改期/转交不跳转；消歧与分级确认 |
| 3 | 智能体跟进（含多智能体共用跟进引擎） | P0 | 每日简报、逾期跟进、主动盯办；各智能体沿用一套跟进逻辑、只管自己创建/关注的任务 |
| 4 | 转交与跟进视角 | P0 | 转交不等于完结；「我转交·跟进中」列表、催办、收回 |
| 5 | 飞书任务双向同步 | P0 | 任务与飞书任务双向同步，任一侧处理结果互通 |
| 6 | 外部业务系统任务接入 | P1 | 客服系统工单等业务任务映射进入统一列表，状态互通 |

## 三、需求正文

### 1. 产品定义

**通用任务模块**是智能体平台的统一任务中心：不论任务由谁创建（人工、群聊识别、skill 产出、智能体、外部业务系统）、是否关联项目空间，都进入同一份任务清单，用同一套状态流转与跟进机制管理。面向角色：销售/售前、解决方案、项目经理、交付/客成等全体平台用户。

任务只有**两个维度，不设任务类型**：
- **来源**：人工创建 / 群聊识别 / skill 产出 / 智能体创建 / 外部系统
- **是否关联项目空间**：关联即出现在项目任务清单，未关联即个人任务

「项目任务」「智能体任务」「个人任务」都是按这两个维度筛选出的视角，而非不同种类的任务。

### 2. 处理流程

**任务产生**：
```
人工创建 / 群聊识别 / skill 拆解 / 智能体创建 / 外部系统推入
→ 关联项目的任务需人工确认后下发（确认时可改处理人与时间）；个人提醒类直接创建
→ 统一进入任务清单，同步生成飞书任务
```

**任务处理**：
```
处理人在工作台对话/任务面板/飞书任一侧处理
→ 无确认人：完成即关闭；有确认人：完成后待确认人确认才关闭
→ 处理结果同步其余各侧
```

**任务跟进**：
```
来源智能体自动盯办：临期提醒 → 逾期升级 → 转交后持续回报进展
→ 用户可对话查询任意任务状态、催办转交任务、关注重点任务
```

### 3. 产品信息结构图

```
通用任务模块
 ├── 统一任务清单（工作台 任务执行-待办）
 │    ├── 我的待办（我是处理人）
 │    └── 我转交 · 跟进中（我转交他人，智能体自动盯）
 ├── 工作台对话交互
 │    ├── 任务查询 → 对话内任务卡片（就地操作）
 │    ├── 每日简报 + 逾期跟进（来源智能体身份触达）
 │    └── 确认卡片（改期/转交等高风险操作先确认）
 ├── 智能体跟进引擎（平台唯一，各智能体共用）
 └── 外部通道
      ├── 飞书任务（双向同步，默认通道）
      └── 外部业务系统（客服工单等，按系统接入配置映射）
```

### 4. 原型及需求说明

#### 4.1 标准任务实体与统一任务列表

**原型：** 整合版原型 · AI 工作台 → 右侧工作空间 → 任务执行 → 待办

**需求说明：**

- **整体功能说明：**
  用户所有待办在同一列表展示，按「我的待办 / 我转交·跟进中」分组；支持按项目、来源、状态、处理人筛选。任务可从工作台对话、项目空间任务清单、飞书任务任一处进入处理。

- **字段说明（标准任务实体）：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 任务名称 | 文本 | 必填 |
| 关联项目空间 | 关联项目，可空 | 为空即个人任务，仅处理人与创建者可见 |
| 处理人 | 飞书用户，可多选 | 至少 1 人；多人任务任一完成即流转（任务级可配置为全部完成才流转） |
| 确认人 | 飞书用户，可无 | 有确认人时，处理人完成后需确认才关闭 |
| 开始/截止时间 | 日期时间，截止精确到时分秒 | 逾期判断依据 |
| 优先级 | 高 / 中 / 低 | 默认中；影响排序与提醒节奏 |
| 来源 | 系统标识 | 人工创建 / 群聊识别 / skill 产出 / 智能体创建 / 外部系统；附来源凭证可溯源（哪条群消息、哪个 skill、哪个工单） |
| 状态 | 系统流转 | 待办 / 执行中 / 待确认 / 已完成 / 逾期 / 阻塞 / 已取消 |

- **逻辑处理说明：**
  - 无确认人：待办 → 执行中 → 已完成；有确认人：待办 → 执行中 → 待确认 →（确认）已完成 /（驳回）执行中
  - 逾期未完成标记「逾期」；任一阶段可标记「阻塞」（需填原因）；可取消
  - 同一任务被多来源重复创建时自动合并去重，不重复出现

#### 4.2 工作台对话查询与就地操作

**原型：** 整合版原型 · AI 工作台 → 会话区（输入「今日任务」「我搞完了」体验）

**需求说明：**

- **整体功能说明：**
  用户在与智能体对话中用自然语言查询任务（「我今天到期的任务」「远航项目逾期的有哪些」），智能体在对话内返回任务卡片；卡片上直接完成、改期、转交、查看详情，处理结果实时回写任务清单与飞书，无需跳转页面。

- **逻辑处理说明：**
  - 任务卡片展示：任务名称、状态、关联项目（个人任务标注）、来源、处理人；支持展开**任务时间线**（创建来源、转交与改期记录、处理人回复），还原任务来龙去脉
  - **渐进筛选**：查询条件在会话中保持，追问「只看高优先级的」是对上一结果的收窄，不是重新查询
  - **空结果给替代口径**：查无结果时主动提供相邻口径（如「今天没有到期的，明天有 3 条，要看吗」）
  - **消歧**：口语操作命中多条任务时（如「我搞完了」），智能体列出候选让用户点选，不猜测执行
  - **操作分级**：完成、标记阻塞等低风险操作直接执行并提供「撤销」；改期、转交等影响他人的操作先出确认卡片，用户确认后生效
  - 对话中的任务卡片可一键**定位到任务面板**（右侧面板切换并高亮该任务）；面板每条任务带「问智能体」入口反向唤起对话
  - 权限边界：用户只能查询、操作自己权限内的任务（关联项目的任务按项目授权，个人任务仅本人），越权查询智能体明确拒绝并说明

---

#### 4.3 智能体跟进与多智能体共用跟进引擎

**原型：** 整合版原型 · AI 工作台 → 进入工作台时的每日简报与逾期跟进卡片；切换智能体应用标签

**需求说明：**

- **整体功能说明：**
  智能体主动把任务盯到闭环，而不是等用户来问：进入工作台时收到今日任务简报；逾期任务由来源智能体发起跟进对话（「这条任务昨天到期了，进展如何？」），用户对话回复即可更新状态；重点任务用户可说「帮我盯着」，状态变化时智能体主动告知。

- **逻辑处理说明：**
  - **每日简报**：用户当天首次进入工作台时推送（逾期 / 今日到期 / 转交跟进中各几条），一键展开卡片列表
  - **逾期跟进**：来源智能体发起跟进，用户回复「已完成」「还要两天」等即更新任务；改期类变更走确认卡片
  - **关注任务**：用户指令「帮我盯着这条任务」后，该任务的状态变化、处理人回复、再次逾期均主动告知
  - **多智能体共用一套跟进引擎**：
    - 跟进逻辑平台唯一（扫描时机、提醒升级、催办话术），新智能体上线自动获得，无需各自配置
    - 每个智能体只跟进**自己创建 + 自己被指定关注**的任务，互不越界；任务创建时记录来源智能体
    - 跟进消息以**来源智能体身份**触达用户，并带「任务来源智能体」标识，用户能分辨是谁在盯这条任务
    - 用户查询任务不受当前会话智能体限制，任一会话可查询权限内全部任务
  - **克制原则**：同一事项合并为一条提醒不重复推送；免打扰时段不推（高级别风险除外）；推送克制规则与群协同一致

---

#### 4.4 转交与跟进视角

**原型：** 整合版原型 · AI 工作台 → 任务执行 → 待办「我转交 · 跟进中」分组；对话输入「我转交的任务怎么样了」

**需求说明：**

- **整体功能说明：**
  转交只是责任转移，不等于任务完结。转交后任务从转出人的「我的待办」移入「我转交 · 跟进中」，转出人可查看处理进展、催办、收回；来源智能体自动继续盯办，对方开始处理、完成、逾期时主动告知转出人。

- **逻辑处理说明：**
  - 「我转交 · 跟进中」展示：当前处理人、处理状态（待处理/进行中）、转交时间、已催办次数
  - **催办**：转出人一键催办，智能体经飞书提醒处理人（附任务卡片与截止时间），对方回复后回告转出人；催办次数留痕
  - **收回**：转出人可将任务收回，任务返回「我的待办」，处理人变更回自己，飞书同步
  - **逾期联动**：转交任务逾期未处理，提醒同时发处理人与转出人；连续逾期按既有升级链上报
  - 转交任务完成时，来源智能体主动告知转出人结果，跟进关闭

---

#### 4.5 飞书任务双向同步

**原型：** 任务卡片「已同步飞书待办」标识

**需求说明：**

- **整体功能说明：**
  平台任务自动同步为飞书任务，用户在飞书侧可直接查看、完成、转交，处理结果双向同步回平台任务清单。用户在任一侧处理，另一侧保持一致。

- **逻辑处理说明：**

| 平台任务状态 | 飞书侧表现 |
|--------------|-----------|
| 待办 / 执行中 | 任务未完成 |
| 待确认 | 保持未完成，备注「等待 {确认人} 确认」，确认后同步完成 |
| 已完成 / 已取消 | 任务完成（已取消附备注） |

  - 任务名称、截止时间等定义类字段以来源方为准；处理状态以用户最后操作的一侧为准并双向回写
  - 同步失败的任务在清单中标注同步异常，支持手动重试；系统每日自动对账，修复漏同步

#### 4.6 外部业务系统任务接入

**原型：** [待补充原型截图]

**需求说明：**

- **整体功能说明：**
  客服系统工单、CRM 跟进任务等外部业务系统的任务，按接入配置映射为平台标准任务，与内部任务同一列表展示处理，状态变化双向互通。用户在任务清单看到外部任务（标注来源系统），可在平台处理并回写，或点击跳转回原系统处理。

- **逻辑处理说明：**
  - **字段映射（以客服工单为例）**：工单号记录为任务来源凭证；SLA 时限映射为截止时间与优先级；工单处理人映射为飞书用户，匹配失败时进入人工认领队列
  - **状态映射**：外部「待处理」→ 待办；「处理中」→ 执行中；「已解决」→ 已完成（有确认人时 → 待确认）；「已关闭」→ 已取消；各系统映射关系可按接入配置调整
  - **处理入口**：纯状态类任务在平台内处理并回写；需在原系统操作的（如工单回复客户），任务卡片提供跳转链接回原系统，平台只同步状态
  - **降级规则**：来源系统不可达或任务在来源侧被取消时，任务标记「阻塞」并注明原因，不自动删除
  - 外部任务的跟进（临期/逾期提醒）同样走智能体跟进引擎，与内部任务体验一致

## 四、关联系统处理

> 本章为技术附录，描述与现有系统的集成，供开发评审使用。

### 与现有平台能力的关系

| 现有能力 | 集成方式 |
|---|---|
| 项目空间 | 关联项目的任务出现在项目任务清单；项目任务创建需按确认人路由表确认后下发（沿用《项目空间能力 v02》4.3） |
| 飞书群智能体 | 群聊识别、提醒升级链、早报机制整体复用；任务跟进引擎与群协同推送同一套克制规则 |
| 智能体执行环境 | 智能体通过任务工具创建/查询/更新任务；写入分级策略（个人提醒直接创建、项目任务确认后下发） |
| AI 工作台 | 对话查询卡片、任务面板分组、简报推送均在工作台呈现（见正文 4.2-4.4） |

### 飞书任务集成

- 平台任务与飞书任务建立映射关系，创建/完成/转交/逾期/待确认状态双向同步
- 正向：任务创建变更时推送飞书；反向：订阅飞书任务变更事件回写平台；每日定时对账兜底
- 智能体查询与跟进范围限于用户授权范围内任务，遵循飞书侧权限约束

### 外部系统接入

- 平台定义任务接入协议（字段映射 + 状态映射 + 回写约定），每个外部系统一个接入配置，映射关系声明式配置，新系统接入不改平台代码
- 接入模式按系统能力三选一：事件推送（实时）、定时拉取（增量）、双向同步（平台操作回写）
- 外部任务以来源系统标识 + 原始单号去重；外部处理人与飞书用户维护账号对照表
- 数据按客户维度隔离，与平台既有权限体系一致

### 一致性与审计

- 任务全变更留痕（操作人/智能体/外部系统、时间、前后值），智能体操作可回溯可撤销
- 智能体批量创建带防重机制，避免重试产生重复任务
