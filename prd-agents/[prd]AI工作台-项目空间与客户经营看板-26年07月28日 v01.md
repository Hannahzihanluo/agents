## 一、概述

### 1.1 需求背景

智能体平台已具备项目空间能力（见《[prd]智能体平台-项目空间能力-26年07月28日 v01》），但项目组成员的日常工作中缺少一个**统一前端**：项目上下文在哪里看、和智能体在哪里对话、待办在哪里处理、需要人工确认的事项在哪里排队。

本需求定义 AI 工作台作为用户应用前端的升级：**我的空间**（项目空间入口与项目会话）、**任务中心**、**消息通知**，以及面向 KA 客户经营的**客户经营看板**——让 AI 从"交付工具"升级为"经营引擎"的三项能力（销售动作指引、三层关系评估、增购机会挖掘）在此呈现。

### 1.2 需求清单

| 序号 | 需求项 | 优先级 | 说明 |
|------|--------|--------|------|
| 1 | 我的空间：项目列表与进入项目空间 | P0 | 按授权过滤，进入即切换项目上下文 |
| 2 | 我的空间：项目会话 | P0 | 默认 KA 智能体，可切换其他应用 |
| 3 | 我的空间：项目文档与云端提交同步 | P1 | 渐进明细视图，产出同步关联 gitlab |
| 4 | 任务中心：待办/执行/记录 | P0 | 汇聚跨项目待办，支持完成与转交 |
| 5 | 消息通知：飞书通知 + 工作台消息 | P0 | 待确认事项形成工作台队列 |
| 6 | 客户经营看板：总览与健康度 | P0 | 关系健康度 + 交付进度 + 风险预警 |
| 7 | 客户经营：三层关系评估 | P0 | 战略层/管理层/执行层关系温度 |
| 8 | 客户经营：销售动作指引 | P1 | 按阶段推送动作建议，可转待办 |
| 9 | 客户经营：增购机会挖掘 | P1 | 业务变化信号 → 方案推荐 → 推送销售 |

## 三、需求正文

### 1. 产品定义

**AI 工作台**是项目组成员的日常统一入口：项目空间及智能体应用在此呈现，用户在这里进入项目、与智能体协作、处理待办、接收需要人工确认的事项。

**客户经营看板**是工作台内面向 KA 项目的经营视图，聚合客户关系健康度、交付进度、风险预警与增购推荐，让销售与项目经理一眼看清"这个客户经营得怎么样、下一步该做什么"。

面向角色：销售/售前、需求调研/解决方案、项目经理、交付/客成，及上级管理者（只读）。

### 2. 处理流程

**日常工作入口**：
```
用户打开工作台 → 我的空间展示有权限的项目列表
→ 选择进入项目 → 工作台切换为该项目上下文
→ 与默认 KA 智能体会话（可切换其他应用）→ 产出生成项目文档
```

**待办与确认闭环**：
```
智能体产出（待办拆解/摘要更新/方案定稿/经营线索）
→ 需要人工确认的事项进入工作台消息队列 + 飞书通知
→ 用户在任务中心处理待办（完成/转交），在消息队列完成确认
```

**客户经营**：
```
智能体持续评估三层关系 + 监听客户业务变化
→ 经营看板更新健康度/动作建议/增购推荐
→ 用户一键转待办或推送销售 → 纳入任务中心跟踪
```

### 3. 产品信息结构图

```
AI 工作台
 ├── 我的空间
 │    ├── 项目（项目列表 → 进入项目空间）
 │    │    ├── 会话：基于本项目上下文 · 默认 KA 智能体 · 可切换模型应用
 │    │    └── 云端提交同步：项目文档产出 → 关联 gitlab
 │    └── 文档：按阶段渐进明细组织
 ├── 任务中心
 │    ├── 待办（跨项目汇聚 · 完成/转交）
 │    ├── 执行（处理过程记录）
 │    └── 记录（历史归档查询）
 ├── 消息通知
 │    ├── 飞书通知（群卡片/@提醒/早报/风险预警）
 │    └── 工作台消息（待确认队列）
 └── 客户经营看板（进入 KA 项目后呈现）
      ├── 总览：健康度 + 交付进度 + 风险预警
      ├── 三层关系评估（战略层/管理层/执行层）
      ├── 销售动作指引
      └── 增购机会挖掘
```

### 4. 原型及需求说明

#### 4.1 我的空间 — 项目列表与进入项目

**原型截图：** [待补充原型截图，原型 v02]

**需求说明：**

- **整体功能说明：**
  用户在工作台「我的空间」看到自己参与的项目列表，每个项目卡片展示项目名称、所属客户、当前阶段、我的角色、待办数量与风险数。点击进入项目空间。

- **逻辑处理说明：**
  - 项目列表按用户在项目空间中的授权过滤，只展示有权限的项目
  - 项目按当前阶段与活跃程度排序，有逾期风险的项目置顶提示
  - 进入项目后，工作台整体切换为该项目上下文：顶栏展示项目名与阶段，会话、文档、看板均指向本项目

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 项目卡片 | 系统生成 | 项目名/客户/阶段/我的角色/待办数/风险数 |
| 项目状态 | 系统标识 | 进行中/已完成/已暂停/已归档 |

---

#### 4.2 我的空间 — 项目会话

**原型截图：** [待补充原型截图，原型 v02]

**需求说明：**

- **整体功能说明：**
  进入项目后，用户与智能体的对话**默认基于本项目上下文**进行——无需重复描述客户背景、项目目标、已确认需求，智能体直接理解"这个项目"的一切。

- **逻辑处理说明：**
  - 项目内会话默认使用 **KA 主理智能体**（已挂载本项目空间），对话自动携带项目统一上下文（客户信息、项目摘要、已确认需求、方案版本）
  - 用户可**切换其他模型应用**（如数据分析、PPT 制作、平台标准智能体），切换后会话仍保留项目上下文
  - 会话产出（报告、方案、分析）可一键保存为项目文档
  - 离开项目空间后，会话恢复为无项目上下文的通用模式

---

#### 4.3 我的空间 — 项目文档与云端提交同步

**原型截图：** [待补充原型截图，原型 v02]

**需求说明：**

- **整体功能说明：**
  项目文档的统一视图：拜访记录、调研报告、方案各版本、POC 报告等按项目阶段渐进明细组织，支持从项目摘要逐层钻取到原文。用户可将文档产出**云端提交同步**，关联 gitlab 保留版本历史。

- **逻辑处理说明：**
  - 文档按阶段分组（调研/方案/POC/交付），每组内按版本排列，当前有效版本置顶
  - 从项目摘要的任一结论可跳转到支撑该结论的原始文档（渐进明细查看）
  - 云端提交同步：用户选择文档发起提交，同步到项目关联的 gitlab 仓库，保留完整版本历史；同步范围限于项目文档产出（方案、报告等）
  - 文档权限与项目授权一致，按客户隔离

---

#### 4.4 任务中心

**原型截图：** [待补充原型截图，原型 v02]

**需求说明：**

- **整体功能说明：**
  汇聚当前用户在**所有项目**中的待办，统一处理入口，支持完成与转交，并保留执行过程与历史记录。

- **逻辑处理说明：**
  - **待办**：按截止时间排序，展示所属项目、优先级、来源（群聊识别/智能体产出/人工创建）；今日到期与逾期置顶标红
  - 待办支持**完成**（标记并可选填完成说明）与**转交**（选择接手人并留言，转交记录保留）
  - **执行**：处理过程记录——开始处理、阻塞标记（填原因）、进展备注，与项目空间任务清单状态实时同步
  - **记录**：历史待办归档查询，支持按项目/状态/时间范围筛选
  - 智能体生成的飞书待办经人工确认下发后，自动出现在责任人任务中心；同时同步至**飞书待办**，用户可在飞书待办中直接完成/转交，状态实时同步回任务中心与项目任务清单

---

#### 4.5 消息通知

**需求说明：**

- **整体功能说明：**
  两类通知通道并行：飞书通知触达群内协同场景，工作台消息承载需要人工处理的事项队列。

- **逻辑处理说明：**
  - **飞书通知**（沿用群智能体通道）：群内卡片、@提醒、每日早报、风险预警
  - **工作台消息**：需要人工确认/处理的事项形成待确认队列——项目摘要更新待确认、方案新版本待审核、任务拆解待确认、增购线索待跟进、经营动作建议
  - 每条工作台消息可直接操作（确认/修改/驳回/转待办），处理后从队列消失并回写对应模块
  - 消息按项目分组，支持一键跳转项目空间对应位置

---

#### 4.6 客户经营看板 — 总览与健康度

**原型截图：** 见试点原型「客户经营」视图

**需求说明：**

- **整体功能说明：**
  进入 KA 项目后，经营看板总览一页呈现：客户关系健康度评分、项目交付进度（里程碑完成率）、客户使用数据、风险预警、增购推荐入口。

- **逻辑处理说明：**
  - 健康度评分由三层关系评估加权得出，展示当前分值与环比变化
  - 交付进度来自项目空间里程碑数据；风险预警聚合商机流失风险与续费风险，按级别展示
  - 预警升级规则：关系温度持续下降达到设定周期，预警升级并通知项目经理

---

#### 4.7 客户经营 — 三层关系评估

**原型截图：** 见试点原型「客户经营」视图

**需求说明：**

- **整体功能说明：**
  按客户组织三层结构分别评估关系经营状态，每层给出关系温度（高/中/低/待激活）与评估依据，帮助销售识别关系短板。

- **逻辑处理说明：**

| 层级 | 评估内容 | 数据来源 |
|------|----------|----------|
| 战略层 | 客户高管战略意图、行业趋势匹配度 | 行业新闻 + 客户动态 |
| 管理层 | 中层管理者对项目的支持度 | 会议频次、反馈质量（来自群消息与纪要） |
| 执行层 | 一线使用者满意度、使用深度 | 产品使用数据（试点期人工录入 + 群事件推断） |

  - 每层温度附带可读的评估依据（如"近 2 周会议频次 2 次/周，但 IT 侧反馈响应变慢"）
  - 执行层在 POC 未开始时显示"待激活"，并给出激活建议
  - 评估结果按周刷新，重大客户动态触发即时重估

---

#### 4.8 客户经营 — 销售动作主动指引

**原型截图：** 见试点原型「客户经营」视图

**需求说明：**

- **整体功能说明：**
  替代销售自行规划动作：智能体按客户所处阶段（CR1-CR7），从标准化动作库输出本周动作建议，并附可直接使用的模板（邀约函、沟通函等）。

- **逻辑处理说明：**
  - 动作建议结合：客户阶段、当前项目进展、三层关系短板（如管理层温度下降 → 建议安排管理层汇报会）
  - 建议附 AI 生成的配套材料初稿（如邀约函），人确认后发出
  - 每条建议可**一键转待办**（自动带入建议负责人与截止时间），进入任务中心跟踪
  - 动作库试点期预置 10-15 条标准动作，运营可维护扩充

---

#### 4.9 客户经营 — 增购机会挖掘

**原型截图：** 见试点原型「客户经营」视图

**需求说明：**

- **整体功能说明：**
  智能体监听客户业务变化信号（融资/扩张/新品上线/组织调整），自动匹配公司方案库中的对应解决方案，生成增购线索推荐给销售。

- **逻辑处理说明：**
  - 每条线索包含：信号内容与来源、匹配的推荐方案、已有验证案例
  - 线索推送给销售负责人（工作台消息 + 飞书私聊），销售确认跟进后转待办
  - 线索处理结果（采纳/搁置/无效）回流记录，用于优化匹配规则

## 四、关联系统处理

> 本章为技术附录，描述与现有系统的集成，供开发评审使用。

### 4.1 与智能体平台的关系

| 平台能力 | 工作台消费方式 |
|---|---|
| 项目空间（上下文/摘要/任务清单） | 我的空间、任务中心的数据来源，状态实时同步 |
| 飞书待办 | 任务中心待办与飞书待办双向同步，用户任一侧处理均实时回写 |
| KA 主理智能体与 skill | 项目会话的默认智能体（按项目挂载对应项目空间）；skill 产出中的待确认事项进入工作台消息队列 |
| 群智能体通知通道 | 飞书通知复用既有通道，不另建 |
| 客户知识空间事件流 | 三层关系评估与增购挖掘的信号来源 |

### 4.2 gitlab 云端提交同步

- 项目文档产出由用户在文档视图主动发起提交，同步至项目关联的 gitlab 仓库，保留版本历史
- 同步为单向（工作台 → gitlab），平台侧项目空间仍是数据权威源
- 同步范围与权限沿用项目授权与客户级数据隔离

### 4.3 数据权限

- 项目列表、文档、看板均按用户在项目空间中的授权过滤
- 经营看板数据按客户隔离，与平台权限体系一致
