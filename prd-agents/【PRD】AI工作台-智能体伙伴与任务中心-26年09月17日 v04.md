## 一、概述

### 1.1 需求背景

AI 工作台是员工日常使用智能体的主入口。随着平台上的智能体数量增长、承接的业务场景变多，工作台暴露出三个问题：

**一是找不到人。** 智能体以横向标签的形式排列，数量超过一屏后需要滚动查找，且每个智能体只有名字，看不出它是干什么的、最近有没有在处理自己的事。用户记不住哪个智能体负责哪件事。

**二是任务散落。** 智能体在对话中识别出的待办、项目空间产生的行动项、业务系统流转过来的工单，分散在不同的对话和页面里。用户没有一个地方能看到"我今天要处理什么"，也无法在一个地方推进这些任务。

**三是看板用不上。** 经营数据分散在各个看板里，用户每次要看都得逐层点进去，常看的看板没有快捷入口。

本需求解决这三个问题：把智能体伙伴改为纵向栏并让每个伙伴自带识别信息与任务动态；新增任务中心作为统一的任务处理场所；新增收藏看板与经营看板，让常看的数据一步可达。

### 1.2 需求清单

| 序号 | 需求项 | 优先级 | 说明 |
|------|--------|--------|------|
| 1 | 智能体伙伴布局变更 | P0 | 横向标签改为纵向伙伴栏，伙伴卡片承载识别信息与任务动态 |
| 2 | 任务中心 | P0 | 统一的任务查看与处理场所，含无限级任务拆解与推进、转交协同 |
| 3 | 收藏看板 | P1 | 常用看板与页面的收藏、置顶、快捷打开 |
| 4 | 经营看板 | P1 | 分组化的经营数据查看入口 |
| 5 | 编辑任务 | P1 | 未办结任务可修改标题、任务描述等信息，修改留痕 |
| 6 | 任务扩展字段 | P1 | 任务详情展示来源系统透传的冗余字段，默认为空，有值才展示 |
| 7 | 列表时间范围 | P1 | 任务中心全部 / 已完成页签默认近 3 个月，待办 / 跟进中不限时间 |

## 三、需求正文

### 1. 产品定义

AI 工作台是员工的**日常工作起点**。用户在这里与智能体伙伴对话获得帮助，在任务中心看到并推进归属自己的工作，在看板区查看经营数据。

三者的关系是同一条工作流的三段：**伙伴**产生和承接工作，**任务中心**推进工作，**看板**呈现工作的结果。

### 2. 处理流程

**任务从产生到办结**

```
任务产生
 ├─ 智能体在对话中识别出待办 → 对话中生成任务卡片
 ├─ 项目空间产生行动项 → 归属到对应项目
 └─ 业务系统流转（case 单 / 客成 / CRM / 天润客服）→ 带业务系统编号进入

任务归集
 → 出现在智能体伙伴卡片的任务动态上（提示"有 N 项待处理"）
 → 同时出现在任务中心左侧列表、任务执行页签的待办列表

处理人推进
 → 打开任务详情
     ├─ 处理：填写处理说明 → 办结（不选执行方）
     ├─ 编辑：修改任务标题、任务描述等信息
     └─ 转交他人
          ├─ 转交但继续跟进：任务转出，自己仍可见、可催办、可收回
          └─ 彻底交接：任务完全移出自己的列表，不可收回

任务拆解（层级不设上限，子任务本身即一个带上级的主任务）
 → 任意节点可继续「+ 添加子任务」，指定处理人
 → 某节点的全部直接下级完成 → 该节点自动办结 → 逐级向上冒泡至主任务
     （各级完成时间取其最后一个完成的下级的完成时间）
 → 或该节点处理人提前人工办结（提示未完成下级数量，确认后不阻断）
     → 其下所有层级未完成的下级逐级自动完成并关闭，状态记为「已完成（随上级关闭）」
 → 已办结节点被重新打开 / 被新增下级 → 其各级上级逐级恢复为进行中

办结后
 → 任务进入「已完成」→ 如需继续跟进可「重新打开」，恢复为待办
```

**看板使用**

```
用户在经营看板中找到常看的看板 → 点击 ☆ 收藏
 → 该看板出现在「我的看板」与工作台我的空间
 → 可置顶，置顶后固定在最前
 → 从收藏位一步打开，不需要逐层进入
```

- 任务中心与智能体平台「任务执行」共用同一份任务数据与处理逻辑
- 看板收藏后同时出现在「我的看板」与我的空间两处

### 4. 原型及需求说明

#### 4.1 智能体伙伴布局变更

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  工作台左侧的智能体入口由横向标签改为纵向伙伴栏。每个伙伴以卡片形式呈现，卡片上除了名称，还展示这个伙伴是干什么的、以及它当前有多少事情等着用户处理。用户扫一眼左栏就能知道该找谁、哪件事更急。

- **逻辑处理说明：**

  **伙伴卡片三元素**

  - 每张卡片包含三部分：头像、名称与一句话职责、任务动态。
  - 一句话职责说明该智能体负责什么，由智能体配置时填写，用于用户快速识别。
  - 任务动态展示该智能体产生或正在处理的任务情况，例如"3 项待处理"。无任务时不展示该行，卡片自动收窄。
  - 点击任务动态区域，直接跳转到任务中心并筛选出该智能体相关的任务，不需要用户自己找。

  **头像生成**

  - 头像不需要人工上传，由系统按智能体名称自动生成，保证同一个智能体在任何位置显示同一个头像。
  - 生成规则保证不同智能体的头像在颜色与图形上有足够区分度，用户可以靠头像辨认伙伴。
  - 头像风格统一，与工作台整体视觉一致。

  **排序与置顶**

  - 伙伴栏默认按用户最近使用时间排序，最近用过的排在前面。
  - 项目类智能体支持置顶。置顶后固定在栏位最前，不受使用时间影响。
  - 置顶状态跟随用户，不同用户各自独立。

  **独立会话**

  - 每个伙伴维护自己独立的会话上下文。切换到另一个伙伴再切回来，原来的对话内容与上下文都还在。
  - 切换伙伴时，如果原伙伴正在执行任务（例如智能体正在处理某个任务），执行不中断，完成后结果仍写回原会话。
  - 每个会话可单独重置。重置只清空该伙伴的会话，不影响其他伙伴，也不影响已产生的任务。

  **@ 切换**

  - 在对话输入框中输入 @ 触发伙伴选择，选中后把当前问题转给该伙伴。
  - @ 切换会把当前对话的相关上下文一并带给新伙伴，用户不需要重新描述背景。

  **任务来源标签**

  - 智能体在对话中识别出待办并生成任务卡片时，该任务带上来源标签，标明它是由哪个伙伴、在哪次对话中产生的。
  - 任务详情中展示来源标签，点击可回到产生它的那次对话，方便处理人回溯上下文。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 智能体名称 | 智能体配置时填写 | 伙伴卡片主标识，也是头像生成的依据 |
| 一句话职责 | 智能体配置时填写，建议 15 字内 | 卡片副标题，帮助用户识别用途 |
| 任务动态 | 系统自动统计 | 展示该伙伴相关的待处理任务数量，无任务时不展示 |
| 置顶状态 | 用户操作，仅项目类智能体支持 | 置顶后固定在栏位最前 |

#### 4.2 任务中心·界面与列表

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  任务中心是用户处理任务的主场所，以全屏左右两区布局呈现：左侧是任务列表，右侧是选中任务的详情，处理时间线放在详情内容的最后一段。用户在一个界面内完成从找任务到办结的全过程，不需要在页面间跳转。

  顶部工具条集中放置状态筛选、名称·编号搜索、「+ 新建任务」、「📌 钉到工作台」与关闭。

- **逻辑处理说明：**

  **归属范围与「处理人视角条目制」**

  - 任务中心只展示归属当前用户的任务，包含两类：自己是处理人（或创建人）的主任务，以及自己创建后转交他人、仍需跟进的任务。
  - **列表条目按处理人视角拉平**：归属自己的子任务，无论它在第几层，都在列表中独立占一条，与主任务同级展示，**不再作为主任务行的缩进附属项**。理由是对处理人来说，一个子任务就是一件要自己做完的事，它的层级位置不影响他的动作。
  - 子任务条目上以「↑ 上级任务：XXX」一行标注它挂在谁下面，用于交代上下文；不归属自己的层级不出现在列表里。
  - 主任务归属自己、其下某个子任务也归属自己时，两者各自成条，互不替代。
  - 通过「彻底交接」转出的任务从列表中完全移出；「转交但继续跟进」的任务保留为跟进态条目。

  **状态筛选与搜索**

  - 顶部提供四个筛选项：**全部 / 待办 / 跟进中 / 已完成**，默认停留在「全部」。
  - 每个筛选项上展示该状态下的条目数量（含子任务条目），数量随状态变化即时刷新。
  - 搜索框支持按任务名称与任务编号检索，与状态筛选叠加生效。
  - 切换筛选时保持当前选中的任务（如果它还在筛选结果内），避免用户丢失位置。

  **时间范围**

  - **全部 / 已完成**两个页签提供时间范围切换，取值为「近 3 个月 / 全部时间」，**默认近 3 个月**。切换入口跟在页签行右侧，标注当前取值。
  - **待办 / 跟进中**两个页签不受时间范围约束，恒展示全部时间。未办结的任务无论创建多久都仍需处理，按时间隐藏会造成漏办；已完成的任务只有回溯价值，默认收窗能让列表回到当期在办的量级。
  - 落窗取的时间按条目状态区分：**已完成条目取完成时间，未完成条目取创建时间**——判断一条已办结的任务是不是近期的事，看的是它什么时候结束。
  - 缺少对应时间的条目不被隐藏，一律视为在窗内，避免历史数据未回填时被筛掉。
  - 页签上的数量与时间范围联动：受约束的页签（全部、已完成）按窗内计数，不受约束的页签（待办、跟进中）按全部计数。
  - 切换时间范围后，若当前选中的条目已不在结果内，自动选中结果中的第一条。
  - 与智能体平台「我的任务」的时间范围是同一套口径，只是承载控件不同（平台侧为筛选区下拉，工作台侧为页签行开关）。

  **排序**

  - 列表先按优先级排序，高 → 中 → 低。
  - 同优先级内按截止时间升序，最早到期的排前面。
  - 无截止时间的任务排在同优先级中有截止时间的任务之后。
  - 超期任务在列表中明显标记，但不改变排序位置，避免用户的心理位置感被打乱。

  **多入口一致性**

  - 任务中心、工作台任务执行页签的待办列表、对话中的任务卡片、智能体平台的任务执行列表，展示的是同一份任务数据。
  - 在任意一处执行处理、转交、重新打开、子任务推进等动作，其余各处即时反映最新状态，不需要用户手动刷新。
  - 各入口的差异仅在展示形态与信息密度：任务中心信息最全，对话卡片最精简。业务规则完全一致。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 任务编号 | 系统生成 | 列表条目首行展示；子任务条目编号为「主任务编号-层级路径」，见 4.5 |
| 任务标题 | 由创建方填写 | 列表主要识别信息 |
| 优先级 | 高 / 中 / 低 | 影响列表排序，列表中以颜色区分 |
| 截止时间 | 由创建方指定，可为空 | 影响列表排序，超期时标记 |
| 任务状态 | 系统流转 | 待办 / 跟进中 / 已完成 |
| 上级任务 | 系统关联 | 子任务条目展示「↑ 上级任务：XXX」；主任务无上级时不展示该行 |
| 处理人 | 由创建任务的一方在创建时指定，可通过转交变更 | 条目上与所属项目同行展示；跟进态展示转交后的接收人 |
| 子任务进度 | 系统自动统计 | 展示「已完成数 / 总数」，可展开查看直接下级；无子任务时不展示 |
| 来源伙伴 | 系统记录 | 对话中产生的任务展示产生它的智能体 |

  **差异说明（原型现状）：** ①原型列表按数据顺序排列（主任务在前、其归属自己的子任务紧随其后），未实现优先级与截止时间排序，本需求按上述排序规则实现；②原型未提供任务取消动作，故筛选项不含「已取消」，取消能力不在本次范围内；③时间范围已按上述规则实现：全部 / 已完成页签展示「🕓 近 3 个月 / 全部时间」切换，待办 / 跟进中页签不出现该切换，页签数量随窗口联动，切换后自动重选首条；原型内补充了两条 3 个月以外的历史已完成任务，用于呈现窗口效果。

#### 4.3 任务中心·任务详情

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  右侧详情区展示选中条目的完整信息与处理入口，处理时间线放在详情内容的最后一段。处理人在这里判断该怎么处理，也在这里回溯别人做过什么。

  因为列表条目分主任务与子任务两类，详情区对应两套视图，**结构一致、范围不同**：主任务详情看整件事，子任务详情只看自己这一环，另附一张上级任务卡片交代上下文。

- **逻辑处理说明：**

  **主任务详情**

  - 自上而下依次为：标题与状态、任务编号、基本信息栏、处理操作按钮、子任务处理节点、任务处理时间线。
  - 基本信息栏字段：任务类型、上级任务（无则显示「无」）、关联项目、业务系统编号、来源、创建时间、截止时间、处理人、创建人、完成时间（已办结时展示）、备注。
  - **关联业务系统编号**是本次新增的重点信息：从业务系统流转过来的任务，展示它在来源系统里的编号，例如「case 单系统 · #8842」。处理人据此回到来源系统核对原始单据。平台内部派生的任务（对话识别、项目行动项）没有业务系统编号，该行不展示。

  **扩展字段**

  - 基本信息栏之后展示「扩展字段」区，呈现来源系统透传的冗余字段（如客户等级、区域、渠道编码等来源系统自定义信息）。
  - **默认为空**，平台不预先定义字段清单、不校验含义，只按来源系统推送的键值原样展示。各业务系统要带的冗余信息差异很大，平台逐个定义永远追不上业务变化。
  - 有值才展示：无扩展字段时整个区块不出现，不留空占位。
  - 扩展字段只读，不参与筛选、排序与统计，也不可在工作台侧编辑。作用是让处理人不切系统就能看到判断所需的上下文。
  - 与智能体平台任务详情的扩展字段是同一份数据、同一套口径。

  **子任务详情**

  - 结构为：标题与状态、任务编号（主任务编号-层级路径）、基本信息栏、处理操作按钮、**上级任务卡片**、本节点的子任务处理节点、该子任务处理记录。
  - 基本信息栏字段：任务类型、上级任务、关联项目、处理人、处理说明、截止时间、来源、子任务进度（有下级时展示）、完成时间（已办结时展示）。
  - **上级任务卡片只展示基本信息**（上级任务编号、名称、状态、处理人、子任务进度），**不作为进入上级任务详情的入口**，卡片上明示「仅展示基本信息，不进入上级任务详情」。这样做是让只负责一个环节的人专注在自己这一环，不被整件事的信息量干扰，也不会误以为自己要对上级任务负责。

  **子任务处理节点（两类详情共用）**

  - 节点区**只列直接下级**，每个节点展示标题、处理人、状态、完成时间，以及可执行的操作。更深层级不在此处铺开，通过节点上的「详情 ›」进入该子任务自己的详情页查看，区头明示「仅列直接下级，更深层级点「详情 ›」进入查看」。这样每一层的信息量都是可控的，不会因为层级深就变成一棵展不完的树。
  - 区头同时展示推进进度「N/M 已完成」，右上提供「+ 添加子任务」。无下级时展示空态提示，仍可添加。
  - 节点上直接提供操作入口，常规动作不需要跳转。

  **处理时间线**

  - 主任务详情的时间线按时间正序记录关键节点：任务创建、分派、编辑、转交、催办、对话中派智能体执行、办结、重新打开。每条记录包含时间、操作人、动作说明。
  - 子任务详情的时间线为**「该子任务处理记录」，只收录本节点相关的动态**，不混入上级任务与兄弟节点的记录，区头明示「仅本子任务相关动态」。记录内容包含：子任务创建并指派处理人（附上级任务名称）、编辑、本节点已拆出的下级数量与完成数、转交与催办、办结或当前处理人；若在对话中派了智能体执行，另记执行与回写。
  - 主任务因子任务全部完成而自动办结时，时间线记录一条说明，写明是自动办结、以及完成时间取自哪个子任务。
  - 在对话中派智能体执行任务时，时间线记录执行开始与执行完成两条，执行完成的记录中包含智能体回写的结果摘要。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 任务编号 | 系统生成 | 主任务为任务号；子任务为「主任务编号-层级路径」，路径逐级追加，见 4.5 |
| 关联业务系统编号 | 由来源系统带入，平台内派生任务为空 | 展示为「来源系统 · 单据号」，为空时不展示该行 |
| 任务类型 | 由创建方指定 | 展示为「业务域 › 来源单据 › 细分场景」，其中细分场景在创建任务时指定 |
| 上级任务 | 系统关联 | 主任务无上级时显示「无」；子任务详情另有上级任务卡片，只读 |
| 处理人 | 由创建子任务的一方在创建时指定，可通过转交或编辑变更 | 子任务的处理人即该节点的问责人，在对话中派智能体执行不改变问责人 |
| 创建人 | 系统记录 | 对话中产生的任务记录产生它的智能体与对话 |
| 任务描述 / 处理说明 | 由创建方填写，**任务描述可在编辑中修改** | 说明要做什么。编辑规则见 4.4「编辑任务」 |
| 扩展字段 | 由来源系统推送时透传，平台不定义清单、不校验、不可编辑 | 冗余字段键值展示，默认为空，有值才展示；不参与筛选与统计 |
| 子任务节点 | 由该节点处理人拆分 | 仅列直接下级，每个节点含标题、处理人、状态、完成时间 |
| 完成时间 | 系统记录 | 人工办结取办结时刻；自动办结取最后一个完成的下级的完成时间 |

#### 4.4 任务中心·任务处理

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  所有任务统一使用一个「处理」按钮作为入口，不再区分「完成」「执行」等多个动作。点击后弹出处理弹窗，**处理人填写处理说明即办结，不需要选择由谁执行**。这样处理人只需要记住一个动作、只填一个字段。

- **逻辑处理说明：**

  **统一处理入口**

  - 任务卡片、任务列表行、任务详情、对话中的任务卡片，都使用同一个「处理」按钮进入同一个处理弹窗。
  - 弹窗内**只有处理说明一项输入**，不再提供「人工处理 / 指派智能体处理」的执行方分叉。

  **处理即办结**

  - 处理人填写处理说明后提交，任务直接办结。处理说明必填，用于向创建人与来源系统说明处理结果。
  - 办结后任务状态变为「已完成」，记录完成时间与处理人，时间线追加一条办结记录。
  - 取消执行方选择的原因是：执行方与任务能否办结无关。处理人要不要让智能体帮忙查一段数据、写一版结论，是发生在对话里的事，办结时要交付的只是一个结论。把执行方做成办结前的一次分叉，等于给最高频的"看一眼、写结论、结单"动作固定加两步，而绝大多数任务并不需要这次选择。
  - 相应地，任务类型配置中的「订阅智能体」一并取消（见《智能体平台 - 任务执行与任务配置》4.3）：既然处理动作不再选智能体，就不需要预先约定某个类型能派给哪些智能体。

  **与对话中派智能体的关系**

  - 需要区分两条链路：**任务的处理动作**不选执行方；**对话中的派智能体**仍然保留。
  - 在与智能体伙伴的对话里，用户可以把某项任务交给智能体去跑，智能体执行完成后把结果回写到会话与任务上，由用户判断是否采纳（可采纳、可重跑）。这条链路的入口在对话，不在任务的处理弹窗。
  - 两者的分工是：对话负责"让智能体干活"，处理弹窗负责"给这件事下结论"。智能体的产出是否写进处理说明，由处理人决定。
  - 无论走哪条链路，**智能体是执行方、不是问责主体**：任务的处理人（问责人）始终不因智能体参与而改变。

  **编辑任务**

  - 未办结任务提供「编辑」，当前用户是处理人或创建人时可用。
  - 可编辑字段：任务标题、**任务描述**、优先级、截止时间、处理人、备注。任务描述是本轮新增的可编辑项——任务从来源系统进来时描述往往只有一句原始摘要，处理人补齐上下文后，转交或接手的人不必再回来源系统翻。
  - 不可编辑字段：任务编号、任务类型、关联业务系统编号、任务状态、创建人、完成时间、扩展字段。这些或由系统生成、或由创建方与来源系统定义，改了会与来源不一致。
  - 编辑中改写处理人等同于转交，按转交规则处理待办与归属。
  - 编辑保存后在时间线记录修改人、时间与变更字段。子任务的编辑记录只进该子任务自己的处理记录。

  **办结后重新打开**

  - 已办结的任务提供「重新打开」。重新打开后任务恢复为待办，回到处理人的待办列表。
  - 重新打开时清空完成时间，时间线记录一条重新打开的记录，包含操作人与时间。
  - 重新打开对来源系统发送状态变更通知。

  **处理权限**

  - 主任务只有主任务的处理人或创建人可以处理。其他人打开任务详情时看不到「处理」按钮，界面提示「主任务处理人为 XXX，仅处理人/创建人可处理主任务」。
  - **子任务的可操作口径为「该节点归我，且它的上级也归我」**：节点自身的处理人是当前用户，同时它的上级节点的处理人也是当前用户（上级是主任务时，看主任务的处理归属）。不满足时只能查看，界面提示「该子任务由 XXX 处理，你只能处理归属自己的子任务」。
  - 这条口径覆盖一个常见场景：当前用户既是主任务处理人、又是其下某个子任务的处理人，此时他在该子任务上可以直接操作，不需要绕回主任务。
  - 主任务处理人不能代替他人办结具体子任务，但可以提前办结自己这一层，此时其下所有未完成下级随之关闭（见 4.5）。
  - 权限判断在所有入口一致：列表条目、详情、子任务节点、对话卡片都按同一规则决定是否展示处理按钮。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 处理说明 | 必填 | 处理弹窗内唯一输入项，向创建人与来源系统说明处理结果，提交即办结 |
| 任务标题 | 编辑时可修改 | 处理人或创建人可改 |
| 任务描述 | **编辑时可修改** | 允许处理人补充上下文，修改留痕于时间线 |
| 执行结果 | 智能体在对话中回写，不可编辑 | 仅对话派智能体的链路产生，采纳与否由用户决定，不影响办结动作 |

  **差异说明（原型现状）：** ①原型的处理说明为选填，本需求要求必填；②处理弹窗已按本轮评审去掉执行方选择，只保留处理说明，提交即办结；原「指派智能体处理」及其「执行完成待确认」环节从处理动作中移除，对话中的派智能体链路保留（原型中智能体执行为前端模拟，结果可采纳、可重跑）；③编辑弹窗已支持修改任务标题与任务描述；④无论走哪条链路，**智能体是执行方、不是问责主体**，不改变该节点的处理人（问责人）。

#### 4.5 任务中心·任务层级与推进

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  任务的拆解**不限定为主任务 + 子任务两级**。核心口径是：**对某个子任务而言，它自己就是一个待处理的主任务，只是多了一个关联的上级任务。** 因此子任务可以继续往下拆，层级不设上限，每一层的处理人在自己那一层拥有完整的处理能力。

  这一节说明层级怎么表达、怎么拆、以及一层完成后如何逐级向上推进。

- **逻辑处理说明：**

  **层级与任务编号**

  - 任务编号体现层级路径：主任务为任务号，其下第 2 个子任务为「任务号-2」，该子任务下第 1 个子任务为「任务号-2-1」，以此类推，层级不设上限。
  - 编号是列表条目、详情、时间线中定位一个节点的唯一标识，用户之间沟通时也以此为准。

  **拆分子任务**

  - 主任务详情与任意子任务详情的子任务节点区都提供「+ 添加子任务」，入口一致，不区分层级。
  - 拆分时填写子任务名称、**指定处理人**、可补充处理说明。该子任务随即进入该处理人的列表，由其负责推进。
  - **不选执行方式**。与 4.4 的处理动作一致，添加子任务不再区分「人执行 / 智能体执行」，只指定处理人——一个子任务必须有人负责，谁来动手是负责人自己的事。需要智能体协助时在对话中调用。
  - 拆分权限沿用 4.4 的可操作口径：能操作该节点的人才能在该节点下拆子任务。

  **逐级冒泡自动办结**

  - 当一个节点的**全部直接下级**都完成时，该节点自动办结；该节点办结后再看它的上级是否已全部完成，**逐级向上冒泡**，一路可以直到主任务自动办结。不需要各层处理人再逐个操作一次。
  - 自动办结的**完成时间取最后一个完成的下级的完成时间**，不取系统触发自动办结的时刻。这样统计口径与实际业务完成时间一致。
  - 自动办结时在对应节点的时间线记录说明，写明共有几个下级、完成时间取自哪一个。
  - 无论下级从哪个入口完成（子任务节点操作、待办列表、对话卡片），都走同一套判断，不存在某条路径漏触发冒泡的情况。

  **重新打开与新增下级的逐级恢复**

  - 已办结的节点可以「重新打开」。重新打开后，它的**各级上级（含主任务）如果已因冒泡而办结，一并恢复为进行中**，并清空各自的完成时间。否则会出现"下级未完成、上级已办结"的自相矛盾状态。
  - 在一个已办结的节点下**新增下级**时同样触发逐级恢复：该节点与它的各级上级都回到进行中。
  - 每次恢复都在对应节点的时间线留下记录。

  **提前人工办结与下级逐级关闭**

  - 节点还有未完成下级时，该节点的处理人仍**可以**人工办结本节点，用于下级已无必要继续的场景。
  - 办结前提示还有 N 个下级未完成，由处理人确认后执行，**不阻断**。
  - **上级办结即下级关闭**：该节点办结后，其下**所有层级**未完成的下级一并自动完成并关闭，逐级向下传递，不只处理直接下级。上级这件事已经了结，下级继续挂在各自处理人的待办里没有意义，也会让待处理量与时效统计失真。
  - 被关闭的下级状态记为**「已完成（随上级关闭）」**，完成时间取上级的办结时间，从各自处理人的列表中移出，不再计入待处理数量。
  - 被关闭下级的处理人收到通知，说明自己的哪个任务因上级办结而关闭、由谁办结，避免"任务凭空消失"。
  - 本节点时间线记录办结动作与被关闭的下级清单；每个被关闭的下级在自己的处理记录中留一条关闭记录，写明关闭原因与触发它的上级。
  - 被关闭的下级仍可「重新打开」，重新打开时按前述规则逐级恢复其各级上级。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 子任务名称 | 由拆分该节点的处理人填写 | — |
| 层级路径 | 系统生成 | 追加在主任务编号之后，逐级追加，层级不设上限 |
| 子任务处理人 | 必选 | 决定该子任务出现在谁的列表里，也是该节点的问责人。不区分人执行 / 智能体执行 |
| 处理说明 | 选填 | 拆分时可交代该子任务要做什么 |
| 子任务状态 | 系统流转 | 待办 / 处理中 / 已完成 / 已完成（随上级关闭） |
| 完成时间 | 系统记录 | 冒泡自动办结时取最后一个完成的下级的时间；随上级关闭时取上级的办结时间 |
| 上级任务 | 系统关联 | 条目与详情中展示，详情中另有只读的上级任务卡片 |

  **差异说明（原型现状）：** ①原型的提前人工办结只提示不拦截，且未实现下级逐级关闭——未完成的下级仍留在各自处理人的列表中。本需求按上述规则实现：上级办结后逐级关闭全部未完成下级；②原型中子任务的转交只变更处理人，不提供「彻底交接」选项（彻底交接仅主任务支持）；③添加子任务弹窗已按本轮评审去掉「人执行 / 智能体执行」选择，只保留处理人与处理说明。

#### 4.6 任务中心·转交与协同

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  任务转交给别人时，用户往往有两种意图：一种是转出去但还想知道进展；另一种是彻底交出去、不再管。这一节把两种意图分开，避免用户转交后既看不到进展、又不知道该找谁。

- **逻辑处理说明：**

  **两种转交方式**

  - 转交时必须明确选择一种方式：
    - **转交但继续跟进** — 任务处理人变更为接收人，但任务仍出现在自己的列表中（跟进态）。自己可以催办、可以收回，但不能代替新处理人办结。
    - **彻底交接** — 任务**完全移出**自己的列表，之后自己不再看到这个任务，也**不能收回**。
  - 选择彻底交接时，界面明确提示这个动作不可逆，避免用户误操作后找不回任务。

  **催办**

  - 跟进态的任务提供「催办」。催办向当前处理人发出提醒，并在时间线记录一条催办记录。
  - 催办有频率限制，同一个任务在短时间内重复催办时提示已催办过，避免打扰。

  **收回**

  - 跟进态的任务提供「收回」。收回后任务的处理人回到自己，任务重新进入自己的待办。
  - 已被对方办结的任务不能收回，如需继续处理走「重新打开」。
  - 通过「彻底交接」转出的任务不出现在自己的列表中，因此不存在收回入口。

  **创建人视角**

  - 自己创建、指派给他人的任务，在列表中以跟进态呈现，操作与转交跟进态一致：可催办、可收回、可查看详情，不能代替处理人办结。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 转交方式 | 必选 | 转交但继续跟进 / 彻底交接（不可收回） |
| 接收人 | 必选 | 转交后的新处理人 |
| 转交说明 | 建议填写 | 说明转交原因，展示在接收人的任务详情中 |

  **差异说明（原型现状）：** 原型的催办无频率限制，可重复点击并累计催办次数；本需求按上述规则加频率限制。

#### 4.7 收藏看板

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  用户把常看的看板、常用的页面、常查的文档收藏起来，之后从固定位置一步打开，不需要每次逐层进入。收藏后的内容同时出现在「我的看板」和工作台我的空间两处。

- **逻辑处理说明：**

  **三类可收藏对象**

  - **看板** — 经营看板下的各类数据看板。
  - **页面** — 工作台内的具体页面（例如某个项目空间的某个页签），收藏时记住进入路径与所在位置，打开后直接回到收藏时的位置。
  - **文档** — HTML 形式的分析报告或方案文档。

  **收藏与取消**

  - 每类对象的标题旁提供 ☆ 图标。未收藏时为空心，收藏后为实心。
  - 点击 ☆ 即时生效，不需要额外保存。取消收藏同样即时生效。
  - 取消收藏不做二次确认，但给出可撤销的提示，用户误点后可一步恢复。

  **两处展示保持一致**

  - 收藏内容在「我的看板」与工作台我的空间两处展示，**两处展示的是同一份收藏清单**，包含全部三类对象。
  - 在任一处收藏或取消，另一处即时同步，不存在两处内容不同的情况。

  **置顶**

  - 收藏项支持置顶。置顶项固定排在收藏清单最前，多个置顶项之间按置顶时间倒序。
  - 未置顶的收藏项按收藏时间倒序，最近收藏的在前。
  - 置顶状态在两处展示位同步。

  **打开方式**

  - 看板与页面类收藏项点击后直接进入对应位置。
  - 文档类收藏项点击后以全屏浮层打开，浮层内可滚动阅读，关闭后回到原来的位置，不打断用户当前的工作。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 收藏名称 | 默认取被收藏对象的标题，允许用户改名 | 改名只影响自己的收藏显示 |
| 收藏类型 | 系统识别 | 看板 / 页面 / 文档 |
| 置顶状态 | 用户操作 | 置顶项排在最前 |
| 收藏时间 | 系统记录 | 未置顶项的排序依据 |

  **差异说明（原型现状）：** 原型中两处展示位的内容范围不同（「我的看板」展示全部三类，我的空间仅展示文档类），且置顶操作只刷新其中一处。本需求按上述规则实现：两处内容与置顶状态完全一致。

#### 4.8 经营看板

**原型截图：**

[待补充原型截图]

**需求说明：**

- **整体功能说明：**

  经营看板是查看业务数据的集中入口。左侧按分组列出可用看板，右侧展示选中看板的内容。用户在这里看经营结果、项目进展、任务处理情况，并把常看的收藏起来。

  - 看板数据按固定周期刷新，页面上标明数据的更新时间，让用户知道看到的是什么时点的数据。

  - 每个看板标题旁提供 ☆ 收藏，规则与 4.7 一致。
  - 看板中的指标支持关联跳转：点击任务量相关指标进入任务中心并带上对应筛选条件；点击项目相关指标进入对应项目空间。跳转后用户能直接看到构成这个数字的具体明细。

- **字段说明：**

| 字段名称 | 填写规则 | 说明 |
|----------|----------|------|
| 看板名称 | 系统预置 | 左侧导航展示 |
| 所属分组 | 系统归类 | 我的看板 / 项目看板 / 任务看板 |
| 数据更新时间 | 系统记录 | 展示在看板顶部 |
| 收藏状态 | 用户操作 | 收藏后进入我的看板分组 |

## 四、关联系统处理

### 4.1 与智能体平台的数据共用

AI 工作台的任务中心与智能体平台的「任务执行」共用同一份任务数据与同一套处理规则，不做数据同步，也不存在两端各存一份的情况。

- 任务的状态流转、权限判断、自动办结规则由统一逻辑处理，两端只负责展示与发起动作。
- 任一端的处理动作（办结、转交、重新打开、子任务推进）在另一端即时可见。
- 平台侧的任务类型配置与业务对接配置，决定了工作台侧任务的来源与参数完整性要求。配置规则见《智能体平台 - 任务执行与任务配置》。
- 任务的处理人由创建方在创建时指定（业务系统推送时带入、平台内派生时由派生方指定），平台不按任务类型派单。工作台侧只按处理人过滤展示，不参与分派。

### 4.2 业务系统任务流转

任务从业务系统进入工作台的校验与结果回写规则，由平台侧统一处理，工作台侧的表现为：

- 通过校验的任务带着**关联业务系统编号**进入处理人的任务列表，编号在任务详情中展示。
- 任务办结后处理结果回写到来源系统。主任务由子任务全部完成自动办结时，回写的完成时间为最后一个子任务的完成时间。
- 任务被重新打开时向来源系统发送状态变更通知。
- 结果回写失败时在任务详情中标记，处理人可以看到回写未成功，避免以为已经同步。

当前已登记且启用中的业务系统：case 单系统、客成系统、CRM、天润客服（业务对接只有启用 / 停用两态，见《智能体平台 - 任务执行与任务配置》4.4）。

### 4.3 对话中派智能体执行任务

这是保留下来的智能体执行链路，入口在与智能体伙伴的对话中，**不是任务的处理动作**（处理动作只填处理说明，见 4.4）。交互约定：

- 智能体在执行期间任务状态为「处理中」，用户可以看到执行进度提示。
- 智能体执行完成后把结果回写到任务与会话上，**不自动办结**：任务停留在待办并提示「执行完成待确认」，由用户判断是否采纳。
- 用户可采纳结果、也可重跑；不采纳时前一次的执行结果保留在时间线中。采纳后要不要就此办结，走 4.4 的处理动作，由处理人自行决定。
- 智能体执行过程中用户切换到其他伙伴或离开工作台，执行不中断，完成后结果仍写回该任务与产生它的会话。
- 执行失败时任务回到待办，时间线记录失败原因，用户可以重跑或自己处理。
- **智能体是执行方、不是问责主体**：无论执行成功还是失败，该任务的处理人（问责人）不变。

### 4.4 状态持久化

工作台的以下状态需要跟随用户保存，用户下次进入时恢复：伙伴栏的置顶与排序、各伙伴的会话上下文、看板收藏与置顶、任务中心的筛选与展开状态。**时间范围不持久化**，每次进入都回到默认的「近 3 个月」——它是一个收窄视野的默认值，被记住后用户容易忘了自己开着「全部时间」。

**差异说明（原型现状）：** 原型未做持久化，刷新页面后上述状态全部回到初始值。本需求要求按用户维度保存。
