## 一、总体框架

### 1.1 试点目标（对齐流程变革目标）

| 目标 | 说明 | 试点验证指标 |
|---|---|---|
| 统一上下文工作 | 项目组所有成员与智能体在同一份项目上下文上工作，信息不再散落群聊/文档/CRM | 项目信息查找时间大幅减少，上下文由 AI 自动维护 |
| 缩短输出交付物时间、提高交付质量、提升赢单率 | 调研→方案→POC 报告全过程 AI 出初稿、人确认 | 调研→方案周期 5 天 → 3 天；AI 产出修正率 ≤ 30% |
| AI 驱动经营 | AI 从交付工具升级为经营引擎：动作指引、三层关系、增购挖掘 | 客户满意度 ≥ 4/5；增购线索产出 |

### 1.2 实现结构：两大主线 × 三个实现层面

```
                        ┌───────────── 智能体平台（能力层）─────────────┐
                        │  资源库：自定义知识库 / 公司知识仓库 /          │
                        │  客户知识空间 / 项目空间                       │
                        │  智能体配置 · 任务执行                         │
                        └──────────────▲────────────────────────────────┘
                                       │ 能力调用 / 数据读写
主线一：流程变革（项目统一上下文）        │
主线二：KA 客户经营             ┌──────┴───────┐        ┌─────────────┐
                        │   AI 工作台   │◀──────▶│  飞书（群/文档） │
                        │ 我的空间·任务中心│  通知   │  群智能体监听   │
                        │ 消息通知       │        └─────────────┘
                        └──────────────┘
                        用户应用前端（人在这里工作）
```

- **智能体平台**：沉淀项目空间能力与全部 skill，是"大脑"
- **AI 工作台**：用户日常工作的统一前端，空间、应用、待办、消息都在这里呈现
- **试点实现方案**：用 1-2 个成熟战略级 KA 项目验证全链路闭环

## 二、主线一：流程变革 —— 项目统一上下文

### 2.1 项目上下文模型

项目空间为每个项目维护一份**统一上下文**，是智能体一切产出的输入基础：

| 组成 | 内容 | 来源 |
|---|---|---|
| 客户信息 | 合同金额、行业、营销阶段（CR1-CR7）、历史对接记录 | 关联 CRM + 客户知识空间，绑定项目时自动带入 |
| 项目摘要 | 项目目标、当前阶段、关键结论、分工、风险概况 | 创建时 AI 生成初稿，运行中自动更新（机制见 2.2） |
| 渐进明细文档 | 拜访记录、调研报告、方案各版本、POC 报告等项目文档 | 按项目阶段渐进沉淀，支持从摘要逐层查看明细 |

### 2.2 群协同与项目信息自动更新

**群协同工作模式**：项目组成员日常仍在飞书群中协同工作，智能体作为群成员**接收全部群消息**，不需要被 @ 也在持续理解项目进展，并**自主判断何时响应、何时保持沉默**：

| 智能体行为 | 触发场景 | 响应方式 |
|---|---|---|
| 主动响应 | 识别到任务分派/承诺确认、关键决策或风险、能直接回答的项目问题、讨论结论需要落锤 | 群内推送卡片或回复（高把握直接写入+确认卡片；中把握先推候选卡片等人确认） |
| 静默处理 | 与项目相关的背景讨论但无需即时动作 | 仅沉淀为上下文输入，不打扰群聊 |
| 完全忽略 | 闲聊等与项目无关内容 | 不处理 |
| 定时行为 | 每日早报、逾期提醒、群置顶摘要更新 | 按配置时间执行（免打扰时段除外） |

**项目信息自动更新机制（AI 提取 + 人工确认）**：

- 智能体持续从**群消息、项目文档变更、CRM 阶段变更**中识别影响项目上下文的变更（如关键决策、需求变更、阶段推进）
- 识别到变更后，智能体生成**更新建议**（改了什么、依据哪条消息/文档），推送给项目经理
- **项目经理确认后写入**项目摘要；所有版本可追溯、可回滚
- 该机制与「AI 输出初稿 → 人确认/修正 → 沉淀」的核心原则一致，避免 AI 误识别污染项目上下文

### 2.3 能力 skill 组（试点期上线 5 个）

| skill | 功能 | 输入 | 产出与确认方式 |
|---|---|---|---|
| 调研方案生成 | 访谈纪要 → 结构化需求标签 → 需求调研报告初稿，关联历史同类项目 | 项目上下文 + 纪要 | 初稿 → 人审核（接受/修改/驳回）→ 定稿沉淀 |
| 需求解决方案 | 基于已确认需求 + 公司方案库，推荐方案框架与类似案例，生成一页纸方案 | 项目上下文 + 公司知识仓库 | 初稿 → 人工迭代（≤3 次）→ 定稿 |
| POC 报告 | 基于 POC 执行数据 + 方案目标，自动生成 POC 验证报告 | 项目上下文 + 交付数据 | 初稿 → 交付确认 → 用于客户立项 |
| 任务拆解 | 从智能体产出/群讨论中拆解行动项，**生成飞书待办** | 方案/报告/群消息 | **必须人工确认**后下发，支持转交 |
| 每周分析总结 | 项目周报：进展、风险、下周计划；修正点复盘 | 项目空间数据 | 自动生成 → 推送项目群 |

前 3 个 skill 对应试点最痛点「需求调研 → 方案输出 → POC」；后 2 个保障执行闭环与复盘迭代。

### 2.4 智能体实现关联

KA 主理智能体（平台唯一，按群挂载项目空间）的能力装配：

| 关联项 | 说明 |
|---|---|
| 标准能力 skill | 平台通用 skill（文档处理、数据分析等）可直接挂载 |
| 公司知识仓库 | 检索方案库、同类项目最佳实践，产出带引用溯源 |
| 关联客户知识空间 | 读取客户背景与历史合作信息；重大决策/里程碑选择性回写 |
| 关联项目空间 | **接收绑定群的全部消息**作为上下文输入源，自主选择性响应（见 2.2）；群内 @智能体 的问答自动定位到本项目上下文 |
| 权限校验 | 基于用户角色/职责校验可查看的项目空间范围，数据按客户隔离 |

## 三、主线二：KA 客户经营

项目空间内置**经营看板**，AI 承担三项经营能力（详细业务逻辑延续试点方案第四章，此处明确平台实现边界）：

| 能力 | 实现方式 | 呈现位置 |
|---|---|---|
| 销售动作主动指引 | 按客户阶段（CR1-CR7）的标准化动作库，AI 自动生成动作建议并附模板（邀约函等），可一键转待办 | 经营看板 + 任务中心 |
| 三层关系评估 | 战略层（行业新闻+客户动态）、管理层（会议频次+反馈质量）、执行层（产品使用数据，试点期人工录入）分别计算关系温度 | 经营看板 |
| 增购机会挖掘 | 监听客户业务变化事件（融资/扩张/新品上线），匹配方案库推荐，推送销售负责人 | 经营看板 + 消息通知 |

经营看板同时聚合：客户关系健康度（三层关系评分）、项目交付进度（里程碑完成率）、风险预警（商机流失/续费）。

## 四、实现层面一：智能体平台 —— 项目空间能力

### 4.1 资源库结构

```
资源库
 ├── 自定义知识库      （已有）
 ├── 公司知识仓库      （已有：准入标准、入库流水线、检索装配）
 ├── 客户知识空间      （已有：CRM 事实层 + 客户事件自动维护）
 └── 项目空间          （本次新建/升级）
      ├── 关联客户      绑定客户后自动带入客户信息与知识空间
      ├── 项目摘要      见 2.2 更新机制（更新 skill 默认配置，可按项目修改）
      ├── 用户授权      角色/职责定义（销售/售前/PM/交付/客成…），关联飞书用户，驱动权限校验
      ├── 任务清单      项目待办（来源：群聊识别/智能体产出/人工创建；关联飞书待办双向同步跟进）
      └── 经营看板      见第三章
```

### 4.2 智能体配置

- 平台存在唯一的 **KA 主理智能体**，服务所有 KA 项目群；项目创建并绑定群后，主理智能体自动入群并将该项目空间挂载到该群，通过群定位上下文，各项目数据相互隔离。可修改的项目级配置：项目摘要更新 skill、群智能体行为参数（沿用已有配置体系）、skill 挂载组合
- 不同营销阶段（CR4 攻坚 / CR5 交付 / CR6 运营）提供预设配置模板

### 4.3 任务执行

- 智能体任务统一进入平台任务执行体系：任务记录、任务报告、执行状态可追踪
- 所有 AI 自动操作可回溯、支持撤销（沿用平台既有要求）

### 4.4 与现有能力的复用结论

| 试点要求 | 结论 |
|---|---|
| 项目空间（基础信息/待办/事件） | 已有 PRD（项目空间与飞书群智能体 v1.2），按本方案补充项目摘要更新机制与经营看板 |
| 群智能体监听/早报/逾期升级 | 零改动复用 |
| 知识入库与检索装配 | 零改动复用；方案库需在基线期录入标杆项目种子数据 |
| 需求/方案/POC 三个生成 skill | **新建**，复用知识提炼与检索链路 |
| 项目摘要自动更新 | **新建**（AI 提取 + 人工确认） |
| 经营看板与三大经营能力 | **新建** |

## 五、实现层面二：AI 工作台 —— 用户应用前端

AI 工作台是项目组成员的日常入口，项目空间及智能体应用在此呈现。

### 5.1 我的空间

**项目**
- 项目列表：展示当前用户有权限的项目空间（按授权角色过滤）
- **选择进入项目空间**后，工作台切换为该项目上下文：
  - **会话基于此项目进行**：与智能体的对话默认携带本项目统一上下文，无需重复描述背景
  - **默认 KA 智能体**：进入项目即默认使用 KA 主理智能体（已挂载本项目空间），**可切换**其他模型应用（如数据分析、PPT 制作）
  - **云端提交同步**：项目文档产出（方案、报告）可提交同步，**关联 gitlab** 仓库，保留版本历史

**文档**
- 项目文档的统一视图：按阶段渐进明细组织，支持从摘要逐层钻取到原文

### 5.2 任务中心

| 模块 | 功能 |
|---|---|
| 待办 | 汇聚当前用户在所有项目中的待办（含智能体生成、人工确认后下发的飞书待办）；支持**完成**、**转交** |
| 执行 | 待办执行过程记录：开始处理、阻塞标记、进展备注 |
| 记录 | 历史待办与完成情况的归档查询 |

### 5.3 消息通知

- **飞书通知**：群内卡片、@提醒、早报、风险预警（沿用群智能体通道）
- **工作台消息**：项目摘要更新待确认、方案迭代待审核、增购线索推送等需要人工处理的事项，在工作台内形成待确认队列

## 六、实现层面三：试点实现方案

### 6.1 试点项目与基线（W1）

- 选定 1-2 个成熟战略级 KA 客户项目（无客户进展风险、配合度高、有历史数据）
- 创建项目空间，绑定客户与飞书群，按角色模板完成用户授权
- 公司知识仓库录入标杆项目种子数据（≥ 10 个同类方案，golden 级）
- KA 主理智能体自动入群并挂载项目空间，完成 skill 挂载与配置

### 6.2 能力上线节奏与验收

| 周次 | 上线内容 | 验收标准 |
|---|---|---|
| W2 | 调研方案生成 skill + 项目摘要自动更新（AI 提取+人工确认） | 需求识别准确率 ≥ 80% |
| W3 | 需求解决方案 skill（方案推荐 + 一页纸方案） | 检索时间减少 50% |
| W4 | AI 工作台项目空间入口 + 任务中心打通飞书待办；经营看板最小版 | 一页纸方案人工修正率 ≤ 30% |
| W5-8 | POC 报告 skill、每周分析总结 skill；经营能力接真实数据；每周复盘迭代提示词 | 调研→方案周期 5 天 → 3 天 |
| W9-10 | 试点报告 + 模板沉淀 + 第二批推广方案 | 可复用模板 ≥ 5 个 |

### 6.3 风险与应对

| 风险 | 应对 |
|---|---|
| 知识库种子数据不足导致推荐不准 | W1 人工录入标杆项目为 golden 级，检索加权 |
| AI 自动更新污染项目上下文 | 更新必须人工确认；版本可追溯可回滚 |
| 跨系统数据打通延迟（产品使用数据等） | 试点期执行层数据人工录入，限定飞书生态内跑通 |
| 客户不配合新工作方式 | 选择战略级信任客户，明确 AI 辅助而非替代人 |
| gitlab 同步与文档权限冲突 | 同步范围限于项目文档产出，沿用客户级数据隔离 |
