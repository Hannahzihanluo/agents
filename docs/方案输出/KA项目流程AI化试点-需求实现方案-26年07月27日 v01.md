## 一、方案定位

基于《KA 项目流程变革 AI 化试点方案》，本文回答一个问题：**试点要用的能力，平台现在有什么、缺什么、先做什么。**

- 不做全量能力建设，只覆盖 MVP 试点 SOP 第 1-3 阶段（第 1-8 周）所需能力
- 优先打透「需求调研 → 方案输出」主线，同步上线客户经营看板的最小可用版本
- 验证的核心闭环：**AI 输出初稿 → 人确认/修正 → 沉淀到知识库**

---

## 二、现有能力盘点与复用映射

| 试点方案要求 | 现有功能 | 复用方式 | 差距 |
|---|---|---|---|
| 项目启动：合作触发自动创建项目空间 | **项目空间**（PRD：项目空间与飞书群智能体 v1.2） | 直接复用。创建项目、绑定客户、绑定飞书群、成员角色模板均已定义 | 缺「确认合作 → 自动创建」的触发链路（当前为手动创建） |
| 关联 CRM 客户数据 | 客户知识空间已打通 CRM 事实层（合同金额、阶段编码） | 项目空间绑定客户后自动带入 | 无 |
| 关联公司知识库 + 客户专属知识空间 | **知识资产管理**（入库流水线、分层存储、检索装配）+ **客户知识空间自动维护** | 直接复用检索装配能力（权限过滤 → 召回 → 重排 → 引用溯源） | 方案库需补充「同类项目最佳实践」种子数据（试点第一阶段人工录入） |
| 项目执行：群消息→待办、每日早报、逾期升级、风险识别 | **飞书群智能体**（消息意图分类、任务分派识别、承诺捕捉、早报、逾期扫描、群摘要） | 直接复用，采用「KA攻坚（CR4）」预设配置 | 无 |
| 会议纪要→需求结构化 | 知识提炼 Agent（提炼为标准文档、自定义提示词） | 复用提炼链路，新建「需求分析」提示词模板 | 缺面向「需求标签」的结构化输出与人工确认界面 |
| 基于需求推荐方案 | 检索装配 + 方案库 | 复用检索能力 | 缺「需求标签 → 方案框架 + 类似案例」的推荐编排 |
| 一页纸方案生成 + 迭代 | 智能体会话/文档生成能力 | 复用 | 缺「一页纸方案」模板与版本迭代记录（v1→v3 修正追踪） |
| 方案定稿沉淀 | 知识入库流水线（received→published）+ 同步客户知识空间 | 直接复用 | 无 |
| 三层关系评估 | 客户知识空间有客户动态与事件流 | 部分复用数据源 | **新建**：三层关系评估模型与温度计算 |
| 增购机会挖掘 | 客户知识空间监听客户业务变化事件 | 复用事件源 | **新建**：业务变化 → 方案匹配的推荐规则 |
| 销售动作主动指引 | 群智能体的定时推送机制 | 复用推送通道 | **新建**：按客户阶段的标准化动作库 |
| 客户健康度看板 | 项目空间看板（待办/风险）已有雏形 | 扩展 | **新建**：关系健康度 + 使用数据 + 增购推荐的聚合看板 |

**结论**：项目执行跟踪链路（群智能体）和知识沉淀链路（知识资产管理）可零改动复用；差距集中在 **KA 参谋长智能体编排、需求→方案的生成链路、客户经营三大能力**。

## 三、需要新建的能力（MVP 范围）

### 3.1 KA 参谋长智能体（编排层）

试点方案中「KA 参谋长智能体副本」的落地形态：**一个绑定了客户知识空间 + 公司知识库 + 项目空间的智能体配置包**，挂载在 AI 能力广场，试点项目创建时一键生成项目专属副本。

| 能力 | 说明 | 对应试点环节 |
|---|---|---|
| 项目初始化 | 确认合作后自动创建项目空间副本，输出初始化摘要、建议分工、待办列表 | 3.1 项目启动 |
| 需求分析 | 访谈纪要 → 结构化需求标签 → 关联历史同类项目，输出需求调研报告初稿 | 3.2 Step 1-2 |
| 方案推荐 | 基于需求标签 + 公司方案库，推荐方案框架与类似案例 | 3.2 Step 3 |
| 方案生成 | 输出一页纸方案初稿，支持迭代（≤3 次），记录每轮人工修正点 | 3.2 Step 4 |
| 沉淀同步 | 定稿自动写入项目空间 + 公司知识库（走入库流水线，人工确认后 published） | 3.2 Step 5 |
| 客户经营 | 销售动作指引、三层关系评估、增购机会挖掘 | 第四章 |

### 3.2 需求调研 → 方案输出链路（核心试点环节）

```
访谈纪要导入（飞书文档/录音转写）
  → AI 提取结构化需求（业务诉求/痛点/约束/期望目标，逐条带原文引用）
  → 人审核：接受 / 修改 / 驳回（驳回项回流重新提取）
  → 需求调研报告初稿 → 人确认
  → AI 推荐方案框架 + Top 3 类似案例（带知识库引用溯源）
  → 一页纸方案初稿 v1 → 人修正 → v2 → 人修正 → v3 定稿
  → 沉淀：项目空间 + 公司知识库 + 客户知识空间
```

**关键设计**：
- 每条 AI 产出都带**来源引用**（纪要原文位置 / 知识库文档），人审核时可一键回溯，这是修正率 ≤30% 达标的前提
- 方案迭代时 AI 展示**本轮修正点摘要**，用于提示词迭代和试点复盘
- 人工修正动作结构化记录（改了哪一段、改成什么），作为后续提示词优化的输入

### 3.3 客户经营看板（最小可用版）

项目空间新增「客户经营」Tab，聚合四类信息：

| 模块 | 内容 | 数据来源 |
|---|---|---|
| 三层关系评估 | 战略层/管理层/执行层关系温度（高/中/低）+ 评估依据 | 行业新闻与客户动态（战略层）、会议频次与反馈质量（管理层）、产品使用数据（执行层，MVP 阶段人工录入 + 群事件推断） |
| 交付与健康度 | 里程碑完成率、当前风险数、功能活跃度 | 项目空间待办/事件数据 |
| 销售动作指引 | 按客户阶段推送标准化动作建议，附模板（邀约函等） | 动作库（新建，试点期预置 10-15 条） |
| 增购推荐 | 识别客户业务变化（融资/扩张/新品上线）→ 匹配方案推荐 | 客户知识空间事件流 + 方案库匹配规则 |

## 四、试点节奏与验收（对齐 MVP SOP）

| 阶段 | 时间 | 平台侧动作 | 验收标准 |
|---|---|---|---|
| 基线建立 | W1 | 创建试点项目空间；标杆项目数据人工录入公司知识库（种子 ≥ 10 个同类方案）；生成 KA 参谋长副本 | 项目空间可用，知识库检索命中 |
| 能力上线 | W2 | 需求分析能力上线 | 需求识别准确率 ≥ 80% |
| | W3 | 方案推荐引擎上线 | 检索时间减少 50% |
| | W4 | 一页纸方案生成上线；客户经营看板最小版上线 | 人工修正量 ≤ 30% |
| 验证迭代 | W5-8 | 每周复盘收集反馈，迭代提示词；三层关系评估接入真实数据 | 调研→方案周期 5 天 → 3 天 |
| 总结沉淀 | W9-10 | 试点报告；可复用模板入库 | 模板 ≥ 5 个 |

## 五、风险与应对（平台侧）

| 风险 | 应对 |
|---|---|
| 知识库种子数据不足导致推荐不准 | W1 人工录入标杆项目为 golden 级知识，检索时 boost |
| AI 产出质量不达标 | 所有产出必须带引用溯源；设置人工审核红线，定稿必须人确认；修正点结构化记录用于周迭代 |
| 跨系统数据打通延迟 | MVP 阶段限定飞书生态（群消息 + 飞书文档），产品使用数据先人工录入 |
| 试点项目外用户误用 | KA 参谋长副本仅对试点项目成员可见（复用知识层权限过滤） |

## 六、原型 Demo 说明

原型页面模拟试点项目「远航物流集团 · 智能调度平台项目」（CR4 阶段）的工作界面，包含 5 个视图：

1. **项目总览** — AI 初始化摘要、建议分工、项目待办
2. **需求调研** — 纪要导入 → AI 提取需求标签（可接受/驳回）→ 调研报告初稿
3. **方案输出** — 方案框架推荐 + 类似案例 → 一页纸方案 v1→v3 迭代 → 定稿沉淀
4. **执行跟踪** — 每日早报、里程碑看板、风险预警（复用群智能体产出）
5. **客户经营** — 三层关系温度、健康度看板、销售动作指引、增购推荐
